### 4.3 Building a Chat Loop: History, Exit, and Errors

---

## 1. What Makes a Chatbot

A single `invoke` answers one question. A **chatbot** repeats a simple cycle until the user leaves:

```text
        +--------------------------------------------------+
        v                                                  |
  1. read the user's message                               |
  2. add it to history                                     |
  3. send the WHOLE history to the model                   |
  4. add the reply to history                              |
  5. print the reply  -------------------------------------+
```

From Lesson 2.2: the model remembers nothing. **The history list is the memory**, and your loop is responsible for it.

> **Mental Model: The Ping-Pong Rally with a Scorekeeper**
> The user and the model hit the ball back and forth. The model forgets every shot as soon as it plays it. The **scorekeeper** (your history list) writes every shot down and reads the whole score sheet to the model before each new shot.

---

## 2. The Four Rules of History

| Rule | Why |
|---|---|
| **1. The system message comes first, once** | It sets the rules for the whole conversation |
| **2. Add the user's message before calling the model** | The model must see the new question |
| **3. Add the reply as a message object, not text** | `history.append(reply)`, never `history.append(reply.text)` |
| **4. If the call fails, remove the unanswered question** | Keeps history as clean question-and-answer pairs |

### Why Rule 3 Matters

LangChain turns plain strings in a message list into **user** messages:

```text
history.append(reply.text)   ->   [system, human: "Hi, I'm Ali", human: "Hello Ali!"]   (wrong)
history.append(reply)        ->   [system, human: "Hi, I'm Ali", ai: "Hello Ali!"]      (right)
```

With the wrong version, the model thinks **the user** said its own replies. Conversations slowly become confused, and nothing crashes, so the bug is easy to miss.

### Why Rule 4 Matters

```text
Without rollback:  [system, human: Q1, ai: A1, human: Q2 (failed), human: Q3, ai: A3]
With rollback:     [system, human: Q1, ai: A1, human: Q3, ai: A3]
```

Two user messages in a row can confuse the model, and some providers reject such a history.

---

## 3. Leaving the Chat Cleanly

| How the user leaves | What Python raises | Handle it with |
|---|---|---|
| Types `exit`, `quit`, or `bye` | Nothing | A check on the input text |
| Presses **Ctrl+C** | `KeyboardInterrupt` | `try` / `except` around `input()` |
| Presses **Ctrl+D** (Windows: **Ctrl+Z**, Enter), or input ends | `EOFError` | The same `except` |
| Presses Enter on an empty line | Nothing | `continue` (ask again) |

Without these, Ctrl+C prints a long, scary traceback instead of "Goodbye!".

---

## 4. When the Model Call Fails

Network apps fail sometimes. Your chat loop must **survive** failures.

| Failure | Typical cause | Temporary? |
|---|---|---|
| Connection refused | Ollama not running | No: user must start it |
| Timeout | Slow network or overloaded server | Often yes |
| Rate limit (HTTP 429) | Too many requests to a cloud provider | Yes: wait and retry |
| Server error (HTTP 5xx) | Provider problem | Often yes |
| Authentication error (HTTP 401/403) | Wrong or missing API key | No: fix `.env` |

**Strategy:**

1. **Retry** temporary failures automatically: `llm.with_retry(stop_after_attempt=2)` retries with a short, growing wait.
2. **Catch** anything that still fails, show a friendly message, and **roll back** the history (Rule 4).
3. **Keep the loop running**: one failed question should not end the whole chat.

> **Mental Model: The Dropped Call**
> When a phone call drops, you don't throw the phone away. You say "sorry, you cut out", call back, and repeat your last sentence. A good chat loop does the same.

---

## 5. Keeping History Under Control

History grows every turn. Long chats cost more and can overflow the context window (Lessons 2.2 and 2.4).

The simplest fix is a **window**: always send the system message, plus only the most recent turns.

```text
Full history:   [system, Q1, A1, Q2, A2, Q3, A3, Q4, A4, Q5]
Sent (2 turns): [system,             Q3, A3, Q4, A4, Q5]
```

The full history is still kept (for `/history` and saving); only the **sent** part is limited. Lesson 2.2 showed smarter options such as token trimming and summarization.

## 6. Examples

All examples use `config.py` from Lesson 4.1. Run them in the `cue-chat` project with `uv run <file>`.

### Example 1: The Minimal Chat Loop

Create `chat_v1.py`:

```python
from config import get_llm

llm = get_llm()

history = [{"role": "system", "content": "You are Cue, a helpful AI assistant. Keep answers short."}]

print("Welcome to Cue Chat! Type 'exit' to quit.")
while True:
    question = input("You: ").strip()

    if not question:
        continue
    if question.lower() in ("exit", "quit", "bye"):
        print("Goodbye!")
        break

    history.append({"role": "user", "content": question})   # 1. add the question
    reply = llm.invoke(history)                             # 2. send the WHOLE history
    history.append(reply)                                   # 3. add the reply MESSAGE (not reply.text)

    print(f"Cue: {reply.text}")
```

Example session (format tested; replies depend on your model):

```text
Welcome to Cue Chat! Type 'exit' to quit.
You: Hi, my name is Ali.
Cue: Hi Ali! How can I help you today?
You: What is my name?
Cue: Your name is Ali.
You: exit
Goodbye!
```

**Try this:** stop Ollama and send a message. The program **crashes** with a long traceback ending in:

```text
httpx.ConnectError: [Errno 111] Connection refused
```

Press Ctrl+C at the `You:` prompt, too: another traceback. Example 2 fixes both.

### Example 2: Safe Exits and Error Recovery

Create `chat_v2.py`:

```python
from config import get_llm

llm = get_llm()

history = [{"role": "system", "content": "You are Cue, a helpful AI assistant. Keep answers short."}]

print("Welcome to Cue Chat! Type 'exit' to quit.")
while True:
    try:
        question = input("You: ").strip()
    except (KeyboardInterrupt, EOFError):  # Ctrl+C, or Ctrl+D / end of input
        print("\nGoodbye!")
        break

    if not question:
        continue
    if question.lower() in ("exit", "quit", "bye"):
        print("Goodbye!")
        break

    history.append({"role": "user", "content": question})
    try:
        reply = llm.invoke(history)
    except Exception as error:
        history.pop()  # remove the question that got no answer
        print(f"Cue: Sorry, something went wrong ({type(error).__name__}). Please try again.")
        continue

    history.append(reply)
    print(f"Cue: {reply.text}")
```

Tested output with Ollama **stopped**:

```text
Welcome to Cue Chat! Type 'exit' to quit.
You: Hi, my name is Ali.
Cue: Sorry, something went wrong (ConnectError). Please try again.
You: bye
Goodbye!
```

| Change from v1 | Effect |
|---|---|
| `try` / `except (KeyboardInterrupt, EOFError)` around `input()` | Ctrl+C and Ctrl+D say "Goodbye!" instead of crashing |
| `try` / `except Exception` around `invoke` | A failed call shows a friendly message; the loop continues |
| `history.pop()` | Removes the unanswered question (Rule 4) |
| `continue` | Goes straight back to the `You:` prompt |

Start Ollama again and continue chatting in the same session: it works, because the loop never stopped.

### Example 3: The Complete Cue Chat

This version adds **commands**, a **history window**, **automatic retries**, and a **token counter**.

Create `chat.py`:

```python
from langchain_core.messages.utils import convert_to_messages

from config import get_llm

SYSTEM_PROMPT = "You are Cue, a helpful AI assistant. Keep answers short."
MAX_TURNS = 10  # one turn = one question + one reply
EXIT_WORDS = ("exit", "quit", "bye")
HELP = "Commands: /help  /history  /reset  /exit"

llm = get_llm().with_retry(stop_after_attempt=2)


def new_history() -> list:
    return [{"role": "system", "content": SYSTEM_PROMPT}]


def recent(history: list) -> list:
    """The system message, the last MAX_TURNS full turns, and the new question."""
    return history[:1] + history[1:][-(MAX_TURNS * 2 + 1):]


def show(history: list) -> None:
    for message in convert_to_messages(history):
        print(f"  [{message.type}] {message.text[:70]}")


history = new_history()
print(f"Welcome to Cue Chat! {HELP}")

while True:
    try:
        question = input("You: ").strip()
    except (KeyboardInterrupt, EOFError):
        print("\nGoodbye!")
        break

    if not question:
        continue

    command = question.lower()
    if command in EXIT_WORDS or command == "/exit":
        print("Goodbye!")
        break
    if command == "/help":
        print(HELP)
        continue
    if command == "/history":
        show(history)
        continue
    if command == "/reset":
        history = new_history()
        print("Cue: Memory cleared. Let's start again.")
        continue

    history.append({"role": "user", "content": question})
    try:
        reply = llm.invoke(recent(history))
    except Exception as error:
        history.pop()
        print(f"Cue: Sorry, I couldn't answer that ({type(error).__name__}). Please try again.")
        continue

    history.append(reply)
    tokens = (reply.usage_metadata or {}).get("total_tokens", "?")
    print(f"Cue: {reply.text}   [{tokens} tokens]")
```

Example session (format tested; replies and token counts depend on your model):

```text
Welcome to Cue Chat! Commands: /help  /history  /reset  /exit
You: Hi, my name is Ali.
Cue: Hi Ali! How can I help?   [27 tokens]
You: What is my name?
Cue: Your name is Ali.   [24 tokens]
You: /history
  [system] You are Cue, a helpful AI assistant. Keep answers short.
  [human] Hi, my name is Ali.
  [ai] Hi Ali! How can I help?
  [human] What is my name?
  [ai] Your name is Ali.
You: /reset
Cue: Memory cleared. Let's start again.
You: What is my name?
Cue: I don't know your name yet.   [26 tokens]
You: /exit
Goodbye!
```

| Feature | Code | Why |
|---|---|---|
| Automatic retry | `get_llm().with_retry(stop_after_attempt=2)` | Temporary failures are retried once before showing an error |
| History window | `recent(history)` | Sends at most the last 10 turns; the full history is kept |
| `/history` | `convert_to_messages(history)` | Shows exactly what the model will "remember", with roles |
| `/reset` | `history = new_history()` | Starts a fresh conversation, keeping the system message |
| Token counter | `reply.usage_metadata` | Watch tokens grow as the conversation gets longer |

**What to notice in the session:** after `/reset`, Cue no longer knows the name. Memory is just the list, and you cleared it.

**Why `-(MAX_TURNS * 2 + 1)` and not `-(MAX_TURNS * 2)`?** `recent()` is called just after the new question is added. With `+ 1`, the window holds the new question plus complete question-and-answer pairs. Without it, the window could start with an AI reply instead of a user message, which some providers reject. Testing caught this exact bug while this lesson was written.

## Key Takeaways

1. A chatbot is a **loop**: read, add to history, send the whole history, add the reply, print.
2. **History is the memory**: system message first, add the question before calling, append the **reply message** (not `.text`), and remove the question if the call fails.
3. Handle **exit words, empty input, Ctrl+C (`KeyboardInterrupt`), and Ctrl+D (`EOFError`)** so the app always ends cleanly.
4. Wrap the model call in **`try` / `except`**, use **`.with_retry()`** for temporary failures, and keep the loop running.
5. Send a **window** of recent turns to control cost and context size; keep the full history for display and saving.
6. Small **commands** (`/history`, `/reset`) make the app easier to use and to debug.

Then test what happens when you stop Ollama halfway through a session and start it again.
