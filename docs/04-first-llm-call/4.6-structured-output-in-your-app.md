### 4.6 Structured Output in Your App

---

## 1. Why Structured Output Inside an App?

In Lesson 3.5 you learned **how** structured output works. This lesson is about **where it fits in a real app** like Cue.

Your **user** reads text. Your **code** needs data: a category to route a ticket, an order number to look up, a yes/no to decide whether to call a human. Structured output turns the model's answer into a **typed Python object** your code can trust.

```text
"I was charged twice for order #4821!"
            |
            v   llm.with_structured_output(TicketInfo)
            |
TicketInfo(category="billing", priority="high", order_number="#4821", summary="Double charge on order")
            |
            v
if info.priority == "high": alert_team(info.order_number)
```

> **Mental Model: The Form at the Counter**
> A customer explains their problem in their own words. The clerk fills in a **form**: category box, priority box, order number box. The form is what the rest of the office works with. `with_structured_output` makes the model fill in your form.

---

## 2. Three Jobs Structured Output Does in an App

| Job | Example in Cue | Schema |
|---|---|---|
| **Extract** facts from free text | Pull category, priority, and order number from a complaint | `TicketInfo` |
| **Decide** what happens next | Route a message to normal chat, tools, or a human | `Route` |
| **Summarize** for storage | Save a conversation summary as JSON for the support team | `ChatSummary` |

The pattern is the same every time:

```python
structured_llm = llm.with_structured_output(MySchema)
result = structured_llm.invoke(...)   # result is a MySchema object, not text
```

---

## 3. How It Works with Ollama

`ChatOllama` uses `method="json_schema"` by default. Testing confirmed that LangChain sends your **Pydantic schema as JSON Schema** in the request's `format` field. Ollama then constrains the model's output to match it, and LangChain turns the reply back into your Pydantic object.

```text
Pydantic class  ->  JSON Schema  ->  sent as "format"  ->  model writes matching JSON  ->  Pydantic object
```

Cloud providers do the same with their own structured output features (Lesson 3.5).

---

## 4. When Structured Output Fails

Even with a schema, things can go wrong: a small model may write text instead of JSON, or miss a required field.

| Without `include_raw` | With `include_raw=True` |
|---|---|
| A bad answer **raises** `OutputParserException` | You get a dictionary: `raw`, `parsed`, `parsing_error` |
| Your app crashes unless you catch it | Your app checks `parsing_error` and chooses a fallback |

Testing confirmed both: when the model replied with plain text, `with_structured_output(...)` raised `OutputParserException`, and with `include_raw=True` the same reply returned `parsed=None` and the error in `parsing_error`.

**In an app, always plan a fallback**: use a default category, ask the user again, or hand over to a human.

> **Mental Model: The Form Comes Back Half-Filled**
> Sometimes the clerk returns a form with boxes left empty or scribbles in the wrong place. A good office has a rule for that: send it back, or pass it to a supervisor. Never file it as if it were correct.

## 5. Examples

### Example 1: The Schemas File

Keep schemas in one file, like tools.

Create `schemas.py`:

```python
from typing import Literal

from pydantic import BaseModel, Field


class TicketInfo(BaseModel):
    """Key facts from one customer message."""

    category: Literal["billing", "delivery", "technical", "account", "other"] = Field(
        description="Main topic. If money is involved, use billing."
    )
    priority: Literal["low", "medium", "high"] = Field(
        description="high if the customer lost money or cannot use the product"
    )
    order_number: str | None = Field(default=None, description="Order number such as #4821, or null if not mentioned")
    summary: str = Field(description="One short sentence describing the problem")


class Route(BaseModel):
    """Which path should handle the user's message."""

    intent: Literal["chat", "tools", "handoff"] = Field(
        description="tools: needs the time, a currency conversion, or an order status. "
                    "handoff: refunds, payment problems, or an upset customer. chat: everything else."
    )
    reason: str = Field(description="One short sentence explaining the choice")


class ChatSummary(BaseModel):
    """A summary of a support conversation."""

    customer_name: str | None = Field(default=None, description="The customer's name, or null if not given")
    topics: list[str] = Field(description="Main topics discussed, 1 to 4 short phrases")
    open_issue: str | None = Field(default=None, description="Anything still unresolved, or null")
    needs_human: bool = Field(description="True if a human agent should follow up")
```

| Design choice | Why |
|---|---|
| `Literal[...]` for categories, priority, intent | The model can only choose allowed values |
| `str | None` with `default=None` | A safe way to say "not mentioned", instead of inventing an order number |
| A `description` on every field | Field descriptions are instructions to the model (Lesson 3.5) |
| A docstring on each class | Becomes the schema's description |

### Example 2: Extract Ticket Facts from Many Messages

Create `so_extract.py`:

```python
from config import get_llm
from schemas import TicketInfo

extractor = get_llm(temperature=0).with_structured_output(TicketInfo)

messages = [
    "I was charged twice for order #4821, please fix this today!",
    "My parcel hasn't arrived yet. Order #5521.",
    "How do I change my email address?",
]

results = extractor.batch(messages)

print(f"{'CATEGORY':<10} {'PRIORITY':<8} {'ORDER':<7} SUMMARY")
for info in results:
    print(f"{info.category:<10} {info.priority:<8} {str(info.order_number):<7} {info.summary}")

print("\nAs a dictionary:", results[0].model_dump())
```

Expected output (values depend on your model):

```text
CATEGORY   PRIORITY ORDER   SUMMARY
billing    high     #4821   Customer was charged twice for one order.
delivery   medium   #5521   Parcel has not arrived yet.
account    low      None    Customer wants to change their email address.

As a dictionary: {'category': 'billing', 'priority': 'high', 'order_number': '#4821', 'summary': 'Customer was charged twice for one order.'}
```

**What to notice:** `batch` (Lesson 4.2) extracts all three in parallel, and each result is a `TicketInfo` object. The third message has no order number, so it is `None` rather than an invented one. `model_dump()` turns the object into a dictionary, ready for a database or a CSV file.

### Example 3: Safe Extraction with a Fallback

Create `so_safe.py`:

```python
from config import get_llm
from schemas import TicketInfo

extractor = get_llm(temperature=0).with_structured_output(TicketInfo, include_raw=True)


def safe_extract(text: str) -> TicketInfo | None:
    """Return a TicketInfo, or None if the model's answer could not be parsed."""
    result = extractor.invoke(text)
    if result["parsing_error"] is not None:
        print(f"  [could not parse: {type(result['parsing_error']).__name__}]")
        print(f"  [raw model text: {result['raw'].text[:60]!r}]")
        return None
    return result["parsed"]


for text in ["I was charged twice for order #4821.", "broken json please"]:
    print(f"Input: {text}")
    info = safe_extract(text)
    print(f"  Result: {info}\n")
```

Tested output (the second input made the test server reply with plain text instead of JSON):

```text
Input: I was charged twice for order #4821.
  Result: category='billing' priority='high' order_number='#4821' summary='Customer reports an issue and wants help.'

Input: broken json please
  [could not parse: OutputParserException]
  [raw model text: 'Sorry, I am not sure how to answer that. ']
  Result: None
```

**What to notice:** the bad reply did **not** crash the program. `safe_extract` returned `None`, and the raw text shows what the model actually wrote, which is very useful for debugging.

### Example 4: A Router That Decides the Path

Use structured output to **choose** what your app does next. One small structured call decides; the right code path runs.

```text
message -> router (Route) -> "tools"   -> tool calling (Lesson 4.5)
                          -> "handoff" -> fixed reply: a human will follow up
                          -> "chat"    -> normal model reply
```

Create `so_router.py`:

```python
from config import get_llm
from schemas import Route
from tools import TOOLS

llm = get_llm(temperature=0)
router = llm.with_structured_output(Route)
tools_by_name = {t.name: t for t in TOOLS}
llm_with_tools = llm.bind_tools(TOOLS)


def handle(message: str) -> str:
    route = router.invoke(message)
    print(f"  [route: {route.intent} | {route.reason}]")

    if route.intent == "handoff":
        return "I've passed this to a human agent, who will reply within 24 hours."

    if route.intent == "tools":
        messages = [{"role": "user", "content": message}]
        reply = llm_with_tools.invoke(messages)
        messages.append(reply)
        for call in reply.tool_calls:
            messages.append(tools_by_name[call["name"]].invoke(call))
        return llm_with_tools.invoke(messages).text if reply.tool_calls else reply.text

    return llm.invoke(message).text


for message in ["What is the status of order #4821?", "I was charged twice, I want a refund!", "What is Python?"]:
    print(f"You: {message}")
    print(f"Cue: {handle(message)}\n")
```

Expected output (wording depends on your model):

```text
You: What is the status of order #4821?
  [route: tools | The user asks for an order status.]
Cue: Your order #4821 (wireless headphones) was delivered on 1 October.

You: I was charged twice, I want a refund!
  [route: handoff | Refund and payment problem.]
Cue: I've passed this to a human agent, who will reply within 24 hours.

You: What is Python?
  [route: chat | A general question.]
Cue: Python is a popular, easy-to-read programming language.
```

**What to notice:** the refund question **never reaches** the normal model. Code decided, based on a typed `intent` value. This is safer than hoping the model's free text says the right thing (Lesson 3.8: the model advises, code decides).

### Example 5: Summarize a Conversation to JSON

Create `so_summary.py`:

```python
import json

from config import get_llm
from schemas import ChatSummary

conversation = [
    {"role": "user", "content": "Hi, my name is Ali."},
    {"role": "assistant", "content": "Hello Ali! How can I help?"},
    {"role": "user", "content": "What is the status of order #4821?"},
    {"role": "assistant", "content": "Order #4821 was delivered on 1 October."},
    {"role": "user", "content": "The headphones were charged twice on my card."},
    {"role": "assistant", "content": "Sorry about that. I'll pass this to our billing team."},
]

summarizer = get_llm(temperature=0).with_structured_output(ChatSummary)

summary = summarizer.invoke(
    [{"role": "system", "content": "Summarize this support conversation."}] + conversation
)

print(summary.model_dump_json(indent=2))

with open("chat_summary.json", "w", encoding="utf-8") as file:
    json.dump(summary.model_dump(), file, indent=2)
print("\nSaved to chat_summary.json")
```

Expected output (values depend on your model):

```text
{
  "customer_name": "Ali",
  "topics": [
    "order status",
    "double charge"
  ],
  "open_issue": "Card charged twice for order #4821",
  "needs_human": true
}

Saved to chat_summary.json
```

**What to notice:** you can pass a **whole message list** to a structured model, not just one string. `model_dump_json(indent=2)` gives readable JSON, and the saved file can be read by any other system.

### Example 6: Cue with a `/summary` Command

This upgrades `chat_tools.py` from Lesson 4.5 into `cue.py`, the complete Cue app for Module 4.

Create `cue.py`:

```python
from langchain.messages import ToolMessage
from langchain_core.messages.utils import convert_to_messages

from config import get_llm
from schemas import ChatSummary
from tools import TOOLS

SYSTEM_PROMPT = "You are Cue, a helpful AI assistant. Use tools when they help. Keep answers short."
MAX_STEPS = 5
EXIT_WORDS = ("exit", "quit", "bye", "/exit")

tools_by_name = {t.name: t for t in TOOLS}
llm_with_tools = get_llm().bind_tools(TOOLS)
summarizer = get_llm(temperature=0).with_structured_output(ChatSummary, include_raw=True)


def run_tool(call: dict) -> ToolMessage:
    tool = tools_by_name.get(call["name"])
    if tool is None:
        return ToolMessage(f"Error: unknown tool '{call['name']}'.", tool_call_id=call["id"], status="error")
    try:
        return tool.invoke(call)
    except Exception as error:
        return ToolMessage(f"Error: {error}", tool_call_id=call["id"], status="error")


def answer(history: list) -> str:
    """Run the tool loop. New messages are appended to history. Raises if the model call fails."""
    for _ in range(MAX_STEPS):
        reply = llm_with_tools.invoke(history)
        history.append(reply)
        if not reply.tool_calls:
            return reply.text
        for call in reply.tool_calls:
            print(f"  [using tool: {call['name']}]")
            history.append(run_tool(call))
    return "Sorry, I could not finish that within the step limit."


def summarize(history: list) -> None:
    """Print a structured summary of the conversation and save it as JSON."""
    conversation = [m for m in convert_to_messages(history) if m.type in ("human", "ai") and m.text]
    if not conversation:
        print("Cue: Nothing to summarize yet.")
        return
    result = summarizer.invoke([{"role": "system", "content": "Summarize this support conversation."}, *conversation])
    if result["parsing_error"] is not None:
        print("Cue: Sorry, I couldn't create a summary this time.")
        return
    summary = result["parsed"]
    with open("chat_summary.json", "w", encoding="utf-8") as file:
        file.write(summary.model_dump_json(indent=2))
    print(f"  Customer:    {summary.customer_name or 'unknown'}")
    print(f"  Topics:      {', '.join(summary.topics)}")
    print(f"  Open issue:  {summary.open_issue or 'none'}")
    print(f"  Needs human: {'yes' if summary.needs_human else 'no'}")
    print("  (saved to chat_summary.json)")


history = [{"role": "system", "content": SYSTEM_PROMPT}]
print("Welcome to Cue! Try: 'What time is it?', 'Convert 50 USD to PKR', or '/summary'. Type 'exit' to quit.")

while True:
    try:
        question = input("You: ").strip()
    except (KeyboardInterrupt, EOFError):
        print("\nGoodbye!")
        break

    if not question:
        continue
    if question.lower() in EXIT_WORDS:
        print("Goodbye!")
        break
    if question.lower() == "/summary":
        try:
            summarize(history)
        except Exception as error:
            print(f"Cue: Sorry, the summary failed ({type(error).__name__}).")
        continue
    if question.lower() == "/history":
        for message in convert_to_messages(history):
            calls = ", ".join(f"asks for {c['name']}" for c in getattr(message, "tool_calls", []))
            print(f"  [{message.type}] {(message.text or calls)[:70]}")
        continue

    turn_start = len(history)  # remember where this turn begins
    history.append({"role": "user", "content": question})
    try:
        print(f"Cue: {answer(history)}")
    except Exception as error:
        del history[turn_start:]  # remove EVERYTHING this turn added: question, tool calls, results
        print(f"Cue: Sorry, something went wrong ({type(error).__name__}). Please try again.")
```

Expected session (the session flow, `/summary` filtering, and JSON saving were tested; wording and summary values depend on your model):

```text
Welcome to Cue! Try: 'What time is it?', 'Convert 50 USD to PKR', or '/summary'. Type 'exit' to quit.
You: /summary
Cue: Nothing to summarize yet.
You: Hi, my name is Ali.
Cue: Hello Ali! How can I help you today?
You: What is the status of order #4821?
  [using tool: get_order_status]
Cue: Your order #4821 (wireless headphones) was delivered on 1 October.
You: /summary
  Customer:    Ali
  Topics:      greeting, order status
  Open issue:  none
  Needs human: no
  (saved to chat_summary.json)
You: exit
Goodbye!
```

| Part | Why |
|---|---|
| Filter to `human` and `ai` messages with text | Tool requests (empty text) and tool results are left out of the summary input |
| `include_raw=True` | A bad summary never crashes the chat |
| `try` / `except` around `summarize` | A connection error during `/summary` keeps the chat running |
| `model_dump_json(indent=2)` | Saves a readable JSON file for the support team |

**What to notice:** `/summary` before any conversation returns "Nothing to summarize yet" without calling the model at all. Checking cheap conditions in code first saves time and tokens.

## Key Takeaways

1. In an app, structured output turns the model's answer into **data your code can use**: `llm.with_structured_output(Schema)`.
2. Three common jobs: **extract** facts, **decide** the next step (routing), and **summarize** for storage.
3. Keep schemas in one file, with **`Literal`** choices, **`None`** for missing facts, and a **description** on every field.
4. Structured calls can fail: use **`include_raw=True`**, check `parsing_error`, and always have a **fallback**.
5. A **router** lets code, not free text, decide what happens next, which is safer and easier to test.
6. You can pass a **whole conversation** to a structured model, and save results with `model_dump()` or `model_dump_json()`.
