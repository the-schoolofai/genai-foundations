### 4.4 Streaming Responses: Chunks, Accumulation, and Failed Turns

---

## 1. Why Stream?

With `invoke`, the user stares at a blank screen until the **whole** answer is ready. With `stream`, words appear as soon as the model writes them.

| | `invoke` | `stream` |
|---|---|---|
| Returns | One `AIMessage` at the end | Many `AIMessageChunk` pieces, one after another |
| User sees text after | The full answer is done | The **first token** (Lesson 2.4: time to first token) |
| Total time | The same | The same |
| Feels | Slow | Fast and alive |

Streaming does not make the model faster. It makes the app **feel** faster, which is why every chat product streams.

> **Mental Model: The Bucket and the Tap**
> `invoke` fills a whole bucket, then hands it to you. `stream` is a tap: water flows the moment it's ready. Same water, but you start drinking much sooner.

---

## 2. Chunks

`llm.stream(...)` returns an **iterator**: a `for` loop receives one `AIMessageChunk` at a time.

```text
llm.stream("Tell me a story")

chunk 1: "Once "
chunk 2: "upon "
chunk 3: "a "
chunk 4: "time"
...
last chunk: ""   + finish reason + token usage
```

Each chunk has the same useful attributes as a message: `.text`, `.content_blocks`, `.response_metadata`, `.usage_metadata`. The **last** chunk usually carries the finish reason and token counts.

---

## 3. Accumulation: Joining Chunks into One Message

For the chat history (Lesson 4.3), you need the **complete** reply as one message. Chunks are designed to be **added together** with `+`:

```python
full = None
for chunk in llm.stream(messages):
    full = chunk if full is None else full + chunk
```

```text
after chunk 1:  full = "Once "
after chunk 2:  full = "Once upon "
after chunk 3:  full = "Once upon a "
...
end:            full = "Once upon a time ..."  + finish reason + tokens
```

`+` joins the text **and** merges the metadata, tokens, and (in Lesson 4.5) tool calls. The LangChain docs use this exact pattern.

The result is still an `AIMessageChunk`. Before saving it to history, convert it to a normal `AIMessage` with `message_chunk_to_message(full)`, so it shows up as a regular `ai` message.

> **Mental Model: Building a Train**
> Each chunk is a carriage. `+` couples the next carriage to the train. When the last carriage arrives (with the "end of train" sign, the finish reason), the train is complete.

---

## 4. Failed Turns: When a Stream Breaks

A stream can end badly in three ways:

| What happens | What you see | How to detect it |
|---|---|---|
| **Error** (server down, network error) | An exception, before or during the stream | `try` / `except Exception` |
| **User stops it** (Ctrl+C while Cue is typing) | `KeyboardInterrupt` during the loop | `except KeyboardInterrupt` |
| **Connection silently cut** | **No error**: the loop just ends early | The joined message has **no finish reason** |

The third case surprised us during testing: when the connection dropped in the middle of a reply, the Ollama client **ended the stream quietly with no exception**. The half-written reply looked like a normal one. The only clue was that `response_metadata` was empty: no `done_reason`, no token counts.

**Rule: a reply is complete only if it has a finish reason.**

```python
def finished(message) -> bool:
    metadata = message.response_metadata
    return bool(metadata.get("finish_reason") or metadata.get("done_reason") or metadata.get("stop_reason"))
```

### What to Do with an Unfinished Reply

**Drop the whole turn**: don't save the partial reply, and remove the user's question too (Rule 4 from Lesson 4.3).

```text
before:      [system, user Q1, ai A1]
add Q2:      [system, user Q1, ai A1, user Q2]
stream breaks after "Once upon a"   ->  drop Q2, don't save the partial text
after:       [system, user Q1, ai A1]
```

Saving half a reply would teach the model that its earlier answer **really ended mid-sentence**, and it may continue from there in strange ways.

> **Mental Model: A Torn Page**
> If a page tears while printing, you don't file the half page in the folder. You throw it away and print again.

### Why Not Retry Automatically?

In Lesson 4.3, `.with_retry()` re-sent failed requests. With streaming, part of the answer is **already on the screen** when a failure happens. Retrying silently would print a second, different answer after the first half. It's clearer to tell the user and let them ask again.

## 5. Examples

All examples use `config.py` from Lesson 4.1. Run them in the `cue-chat` project with `uv run <file>`.

### Example 1: `invoke` vs `stream`

Create `stream_basics.py`:

```python
import time

from config import get_llm

llm = get_llm()
question = "Tell me a two-sentence story about a coder in Lahore."

# 1. invoke: wait for the whole answer
start = time.perf_counter()
reply = llm.invoke(question)
print(f"invoke: waited {time.perf_counter() - start:.2f} s, then got everything at once")
print(reply.text, "\n")

# 2. stream: print each piece as soon as it arrives
start = time.perf_counter()
first_piece_at = None
for chunk in llm.stream(question):
    if first_piece_at is None and chunk.text:
        first_piece_at = time.perf_counter() - start
    print(chunk.text, end="|", flush=True)

print(f"\n\nstream: first piece after {first_piece_at:.2f} s, finished after {time.perf_counter() - start:.2f} s")
```

Tested output (timings from the test server; yours will differ):

```text
invoke: waited 1.19 s, then got everything at once
Once upon a time in Lahore, a young coder named Sara built a chatbot. ...

Once |upon |a |time |in |Lahore, |a |young |coder |named |Sara |built |a |chatbot. | ...

stream: first piece after 0.30 s, finished after 1.18 s
```

**What to notice:** the **total** time is almost identical, but streaming showed the first word about four times sooner. The `|` marks show where each chunk ends.

| Code | Meaning |
|---|---|
| `for chunk in llm.stream(question)` | Receive chunks one by one |
| `print(..., end="", flush=True)` | Stay on the same line and show text immediately |

### Example 2: Join Chunks into a Full Message

Create `stream_accumulate.py`:

```python
from config import get_llm

llm = get_llm()

full = None
count = 0
for chunk in llm.stream("In one sentence, what is streaming?"):
    print(chunk.text, end="", flush=True)
    full = chunk if full is None else full + chunk
    count += 1

print("\n")
print("Chunks received:", count)
print("One chunk is a:  ", type(chunk).__name__)
print("Joined result is:", type(full).__name__)
print("Full text:       ", full.text)
print("Tokens:          ", full.usage_metadata)
print("Finish reason:   ", full.response_metadata.get("done_reason") or full.response_metadata.get("finish_reason"))
```

Example output (format tested; your text and counts will differ):

```text
Streaming means sending the answer in small pieces as it is generated.

Chunks received: 9
One chunk is a:   AIMessageChunk
Joined result is: AIMessageChunk
Full text:        Streaming means sending the answer in small pieces as it is generated.
Tokens:           {'input_tokens': 20, 'output_tokens': 7, 'total_tokens': 27}
Finish reason:    stop
```

**What to notice:** after joining, `full` has the complete text **and** the token counts and finish reason from the last chunk.

**Note for OpenAI models:** `ChatOpenAI` only includes token usage in streams when you opt in with `stream_usage=True` (see the LangChain OpenAI integration docs).

### Example 3: Detecting a Broken Stream

This example asks for a story while the connection drops partway through. On your machine, you can simulate it by **stopping Ollama while the reply is printing**.

Create `stream_failure.py`:

```python
from config import get_llm

llm = get_llm()


def finished(message) -> bool:
    """A complete reply carries a finish reason. A cut-off stream does not."""
    metadata = message.response_metadata
    return bool(metadata.get("finish_reason") or metadata.get("done_reason") or metadata.get("stop_reason"))


history = [{"role": "system", "content": "You are Cue, a helpful assistant."}]
history.append({"role": "user", "content": "Tell me a story, then crash."})

print("Cue: ", end="", flush=True)
full = None
error_name = None
try:
    for chunk in llm.stream(history):
        print(chunk.text, end="", flush=True)
        full = chunk if full is None else full + chunk
except Exception as error:
    error_name = type(error).__name__

print()
if error_name is None and full is not None and full.text and finished(full):
    history.append(full)
    print("Complete reply: saved to history.")
else:
    history.pop()
    reason = f"error: {error_name}" if error_name else "no finish reason, so the stream was cut off"
    received = full.text if full is not None else ""
    print(f"Incomplete reply ({reason}). Dropped the turn; {len(received.split())} partial words were NOT saved.")

print("Messages in history:", len(history))
```

Tested output when the connection was cut mid-reply:

```text
Cue: Once upon a time in Lahore,
Incomplete reply (no finish reason, so the stream was cut off). Dropped the turn; 6 partial words were NOT saved.
Messages in history: 1
```

Tested output when Ollama was not running:

```text
Cue:
Incomplete reply (error: ConnectError). Dropped the turn; 0 partial words were NOT saved.
Messages in history: 1
```

**What to notice:** in the first case **no exception was raised**. Without the `finished()` check, the half story would have been saved as a normal reply.

### Example 4: Cue Chat with Streaming

This upgrades `chat.py` from Lesson 4.3. Everything else stays the same; the model call becomes `stream_reply()`.

Create `chat_stream.py`:

```python
from langchain_core.messages import message_chunk_to_message
from langchain_core.messages.utils import convert_to_messages

from config import get_llm

SYSTEM_PROMPT = "You are Cue, a helpful AI assistant. Keep answers short."
MAX_TURNS = 10
EXIT_WORDS = ("exit", "quit", "bye")
HELP = "Commands: /help  /history  /reset  /exit   (Ctrl+C while Cue is typing stops the reply)"

llm = get_llm()


def new_history() -> list:
    return [{"role": "system", "content": SYSTEM_PROMPT}]


def recent(history: list) -> list:
    return history[:1] + history[1:][-(MAX_TURNS * 2 + 1):]


def show(history: list) -> None:
    for message in convert_to_messages(history):
        print(f"  [{message.type}] {message.text[:70]}")


def finished(message) -> bool:
    metadata = message.response_metadata
    return bool(metadata.get("finish_reason") or metadata.get("done_reason") or metadata.get("stop_reason"))


def stream_reply(messages: list):
    """Print the reply as it arrives. Return the full message, or None if it did not finish."""
    print("Cue: ", end="", flush=True)
    full = None
    try:
        for chunk in llm.stream(messages):
            print(chunk.text, end="", flush=True)
            full = chunk if full is None else full + chunk
    except KeyboardInterrupt:
        print("\n[stopped]")
        return None
    except Exception as error:
        print(f"\n[error: {type(error).__name__}. Please try again.]")
        return None
    print()
    if full is None or not full.text:
        return None
    if not finished(full):
        print("[connection lost: the reply was incomplete. Please try again.]")
        return None
    return message_chunk_to_message(full)  # a normal AIMessage for history


history = new_history()
print(f"Welcome to Cue Chat! {HELP}")

while True:
    try:
        question = input("You: ").strip()
    except (KeyboardInterrupt, EOFError):
        print("\nGoodbye!")
        break

    if not question:
        continue

    command = question.lower()
    if command in EXIT_WORDS or command == "/exit":
        print("Goodbye!")
        break
    if command == "/help":
        print(HELP)
        continue
    if command == "/history":
        show(history)
        continue
    if command == "/reset":
        history = new_history()
        print("Cue: Memory cleared. Let's start again.")
        continue

    history.append({"role": "user", "content": question})
    reply = stream_reply(recent(history))

    if reply is None:
        history.pop()  # drop the unfinished turn
    else:
        history.append(reply)
```

| Part | What it does |
|---|---|
| `stream_reply()` | Streams, joins chunks, and returns a complete `AIMessage` or `None` |
| `except KeyboardInterrupt` **inside** `stream_reply` | Ctrl+C while Cue is typing stops **only the reply**, not the whole app |
| `finished(full)` | Catches silently cut-off streams |
| `message_chunk_to_message(full)` | Saves a normal `AIMessage` (type `ai`) instead of a chunk |
| `if reply is None: history.pop()` | Drops unfinished turns |

Tested session (Ctrl+C pressed while the story was printing):

```text
Welcome to Cue Chat! Commands: /help  /history  /reset  /exit   (Ctrl+C while Cue is typing stops the reply)
You: Tell me a story.
Cue: Once upon a time in Lahore, a young coder named
[stopped]
You: /history
  [system] You are Cue, a helpful AI assistant. Keep answers short.
You: /exit
Goodbye!
```

**What to notice:** Ctrl+C now has **two meanings**. While Cue is typing, it stops the reply and the chat continues. At the `You:` prompt, it leaves the app (Lesson 4.3). The stopped turn left no trace in the history.

## Key Takeaways

1. **Streaming** shows text as soon as it's generated; total time is the same, but the app feels much faster.
2. `llm.stream()` yields **`AIMessageChunk`** pieces; print `chunk.text` with `end=""` and `flush=True`.
3. **Join chunks with `+`** to get the full text, metadata, and token counts; convert with `message_chunk_to_message` before saving to history.
4. A stream can fail with an **error**, a **Ctrl+C**, or a **silent cut-off**. A reply is complete only if it has a **finish reason**.
5. **Drop unfinished turns**: don't save partial replies, and remove the unanswered question.
6. Catch `KeyboardInterrupt` **inside** the streaming function, so Ctrl+C stops the reply without closing the app.
