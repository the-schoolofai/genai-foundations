### 4.5 Tool Calling: @tool, bind_tools, and the Manual Tool Loop

---

## 1. What Is Tool Calling?

An LLM can only produce text. It can't check the clock, look up an order, or do exact currency maths. **Tool calling** lets the model **ask your code** to do those things.

The model never runs anything itself. It writes a **request**: "please run `convert_currency` with amount 100, from USD, to PKR". **Your code** runs the function and sends the result back.

```text
You:   "Convert 100 USD to PKR"
         |
         v
Model: "I need a tool"  ->  tool_calls = [convert_currency(amount=100, from=USD, to=PKR)]
         |
         v
Your code runs convert_currency(...)  ->  "100.00 USD = 28,000.00 PKR"
         |
         v
Model reads the result  ->  "100 US dollars is 28,000 Pakistani rupees."
```

> **Mental Model: The Manager and the Assistant**
> The model is a manager who can't leave the office. It writes a note: "Please check order #4821." Your code is the assistant who goes, checks, and brings back the answer. The manager then writes the reply to the customer. **The manager only writes notes; the assistant does the work.**

You will also hear this called **function calling**. In the LangChain docs, both names mean the same thing.

---

## 2. The Three Parts

| Part | LangChain | What it does |
|---|---|---|
| **Define** a tool | `@tool` | Turns a Python function into a tool with a name, description, and argument schema |
| **Bind** tools to a model | `llm.bind_tools([...])` | Tells the model which tools exist and how to call them |
| **Run** the loop | Your code | Reads `reply.tool_calls`, runs each tool, sends back `ToolMessage` results, repeats |

---

## 3. Defining Tools with `@tool`

```python
@tool(parse_docstring=True)
def convert_currency(amount: float, from_currency: str, to_currency: str) -> str:
    """Convert an amount of money from one currency to another.

    Args:
        amount: How much money to convert, for example 100.
        from_currency: Currency code to convert from: PKR, USD, EUR, or AED.
        to_currency: Currency code to convert to: PKR, USD, EUR, or AED.
    """
```

| Part of the function | Becomes | Why it matters |
|---|---|---|
| Function name | The tool's **name** | Use `snake_case`; some providers reject spaces or special characters |
| First line of the docstring | The tool's **description** | The model reads this to decide **when** to use the tool |
| Type hints (`float`, `str`) | The **argument schema** | Required: they tell the model what type each argument must be |
| `Args:` section (with `parse_docstring=True`) | **Argument descriptions** | Tells the model what each argument means |

**Testing caught an important detail:** without `parse_docstring=True`, the `Args:` descriptions are **not** sent to the model; only names and types are. Use `parse_docstring=True` whenever your docstring describes the arguments.

> **Mental Model: The Job Advert**
> The name and description are a job advert the model reads before hiring a tool. A vague advert ("does stuff") means the wrong tool gets hired, or none at all.

---

## 4. What the Model Sends Back

When the model wants a tool, its reply has **empty text** and a list of **tool calls**:

```python
reply.text        # ''
reply.tool_calls  # [{'name': 'convert_currency',
                  #   'args': {'amount': 100.0, 'from_currency': 'USD', 'to_currency': 'PKR'},
                  #   'id': 'fe9e56e0-...',
                  #   'type': 'tool_call'}]
```

| Key | Meaning |
|---|---|
| `name` | Which tool to run |
| `args` | The arguments, already parsed into a dictionary |
| `id` | A unique ID that links the result back to this request |

The model can ask for **several tools in one reply** (parallel tool calls), for example the time **and** a currency conversion.

### Sending Results Back: `ToolMessage`

`tool.invoke(call)`, given the **whole** tool call, runs the function and returns a `ToolMessage` whose `tool_call_id` matches the request's `id`. That is how the model knows which result belongs to which request.

---

## 5. The Manual Tool Loop

The model may need several rounds: call a tool, read the result, call another tool, then answer. So the pattern is a **loop**:

```text
repeat (at most MAX_STEPS times):
    reply = model(history)
    add reply to history
    if reply has no tool calls:  -> this is the final answer, stop
    for each tool call:
        run the tool, add its ToolMessage to history
```

### Four Safety Rules

| Rule | Why |
|---|---|
| **Cap the steps** (`MAX_STEPS`) | A confused model can ask for tools forever; each step costs time and tokens |
| **Check the tool name** | The model can invent a tool that doesn't exist |
| **Catch tool errors** and return them as a `ToolMessage` with `status="error"` | The model can read "No order found" and explain it, instead of the app crashing |
| **Roll back the whole turn** if the model call fails | One turn can add many messages: question, tool calls, results. Remove all of them |

> **Mental Model: The Errand Runner with a Budget**
> Send the assistant on errands, but give them a limit: "at most five trips". If a shop is closed, they come back and **report** it, rather than disappearing.

---

## 6. Choose a Model That Supports Tools

Not every model can call tools. `gemma3:1b`, used in earlier lessons, **does not** support tool calling in Ollama; Ollama returns an error saying the model does not support tools. Switch `.env` to a tool-capable model:

```dotenv
MODEL_NAME=ollama:gemma4:e2b
```

`gemma4` lists **tools** among its capabilities in the Ollama library (Lesson 1.2). For cloud models, check `llm.profile["tool_calling"]` (Lesson 4.2), for example `google_genai:gemini-3.5-flash-lite` reports `True`.

### Example 1: The Tools File

Keep tools in their own file, so every script can import them.

Create `tools.py`:

```python
from datetime import datetime

from langchain.tools import tool

RATES_TO_PKR = {"PKR": 1.0, "USD": 280.0, "EUR": 305.0, "AED": 76.0}  # example rates for practice

ORDERS = {
    "#4821": "Wireless headphones: delivered on 1 October.",
    "#5521": "School backpack: out for delivery, arriving today.",
}


@tool
def get_current_time() -> str:
    """Return the current local date and time."""
    return datetime.now().strftime("%A, %d %B %Y, %H:%M")


@tool(parse_docstring=True)
def convert_currency(amount: float, from_currency: str, to_currency: str) -> str:
    """Convert an amount of money from one currency to another.

    Args:
        amount: How much money to convert, for example 100.
        from_currency: Currency code to convert from: PKR, USD, EUR, or AED.
        to_currency: Currency code to convert to: PKR, USD, EUR, or AED.
    """
    source, target = from_currency.upper(), to_currency.upper()
    if source not in RATES_TO_PKR or target not in RATES_TO_PKR:
        raise ValueError(f"Unsupported currency. Use one of: {', '.join(RATES_TO_PKR)}")
    result = amount * RATES_TO_PKR[source] / RATES_TO_PKR[target]
    return f"{amount:,.2f} {source} = {result:,.2f} {target}"


@tool(parse_docstring=True)
def get_order_status(order_number: str) -> str:
    """Look up the delivery status of a ShopPK order.

    Args:
        order_number: The order number, for example #4821.
    """
    key = order_number if order_number.startswith("#") else f"#{order_number}"
    if key not in ORDERS:
        raise ValueError(f"No order found with number {key}.")
    return ORDERS[key]


TOOLS = [get_current_time, convert_currency, get_order_status]
```

| Design choice | Why |
|---|---|
| `raise ValueError(...)` for bad input | The tool loop turns errors into messages the model can read |
| Fixed example `RATES_TO_PKR` | Keeps the lesson offline; a real app would call a rates API |
| `TOOLS` list | One place to add or remove tools |

### Example 3: One Tool Call, Step by Step

This follows the three steps from the LangChain docs: the model asks, your code runs the tool, the model answers.

Create `tool_single.py`:

```python
from config import get_llm
from tools import TOOLS

tools_by_name = {t.name: t for t in TOOLS}
llm_with_tools = get_llm(temperature=0).bind_tools(TOOLS)

messages = [{"role": "user", "content": "Convert 100 USD to PKR."}]

# Step 1: the model decides to call a tool
ai_message = llm_with_tools.invoke(messages)
messages.append(ai_message)
print("Model text:     ", repr(ai_message.text))
print("Model asks for: ", ai_message.tool_calls)

# Step 2: YOUR code runs each requested tool
for call in ai_message.tool_calls:
    tool_message = tools_by_name[call["name"]].invoke(call)  # returns a ToolMessage
    messages.append(tool_message)
    print("Tool result:    ", tool_message.content, "| for call id", tool_message.tool_call_id)

# Step 3: the model writes the final answer using the results
final = llm_with_tools.invoke(messages)
print("Final answer:   ", final.text)
```

Tested output (IDs differ every run; the final wording depends on your model):

```text
Model text:      ''
Model asks for:  [{'name': 'convert_currency', 'args': {'amount': 100.0, 'from_currency': 'USD', 'to_currency': 'PKR'}, 'id': 'de711ffe-5010-48ed-a9a2-b921d00fc055', 'type': 'tool_call'}]
Tool result:     100.00 USD = 28,000.00 PKR | for call id de711ffe-5010-48ed-a9a2-b921d00fc055
Final answer:    Here is what I found: 100.00 USD = 28,000.00 PKR 
```

**What to notice:** in step 1 the model's text is **empty**: it only asked for a tool. The final answer arrives only after your code sends back the `ToolMessage`.

### Example 4: The Safe Tool Loop

Create `tool_loop.py`:

```python
from langchain.messages import ToolMessage

from config import get_llm
from tools import TOOLS

MAX_STEPS = 5

tools_by_name = {t.name: t for t in TOOLS}
llm_with_tools = get_llm(temperature=0).bind_tools(TOOLS)


def run_tool(call: dict) -> ToolMessage:
    """Run one tool call safely. Errors go back to the model as text, not as a crash."""
    tool = tools_by_name.get(call["name"])
    if tool is None:
        return ToolMessage(f"Error: unknown tool '{call['name']}'.", tool_call_id=call["id"], status="error")
    try:
        return tool.invoke(call)
    except Exception as error:
        return ToolMessage(f"Error: {error}", tool_call_id=call["id"], status="error")


def ask(question: str) -> str:
    messages = [
        {"role": "system", "content": "You are Cue. Use tools when they help. Keep answers short."},
        {"role": "user", "content": question},
    ]
    for step in range(1, MAX_STEPS + 1):
        reply = llm_with_tools.invoke(messages)
        messages.append(reply)

        if not reply.tool_calls:  # no tools needed: this is the final answer
            return reply.text

        for call in reply.tool_calls:
            result = run_tool(call)
            messages.append(result)
            print(f"  [step {step}] {call['name']}({call['args']}) -> {result.content}")

    return "Sorry, I could not finish that within the step limit."


for question in [
    "What time is it, and convert 100 USD to PKR?",  # two tools in one step
    "What is the status of order #4821?",           # one tool
    "What is the status of order #9999?",           # the tool raises an error
    "In one sentence, what is Python?",             # no tool needed
    "Check the time, then loop forever.",           # never stops asking: hits MAX_STEPS
]:
    print(f"You: {question}")
    print(f"Cue: {ask(question)}\n")
```

Tested output (times will differ; the final wording depends on your model):

```text
You: What time is it, and convert 100 USD to PKR?
  [step 1] get_current_time({}) -> Saturday, 10 October 2026, 23:29
  [step 1] convert_currency({'amount': 100.0, 'from_currency': 'USD', 'to_currency': 'PKR'}) -> 100.00 USD = 28,000.00 PKR
Cue: Here is what I found: Saturday, 10 October 2026, 23:29 | 100.00 USD = 28,000.00 PKR 

You: What is the status of order #4821?
  [step 1] get_order_status({'order_number': '#4821'}) -> Wireless headphones: delivered on 1 October.
Cue: Here is what I found: Wireless headphones: delivered on 1 October. 

You: What is the status of order #9999?
  [step 1] get_order_status({'order_number': '#9999'}) -> Error: No order found with number #9999.
Cue: Here is what I found: Error: No order found with number #9999. 

You: In one sentence, what is Python?
Cue: Python is a popular, easy-to-read programming language. 

You: Check the time, then loop forever.
  [step 1] get_current_time({}) -> Saturday, 10 October 2026, 23:29
  [step 2] get_current_time({}) -> Saturday, 10 October 2026, 23:29
  [step 3] get_current_time({}) -> Saturday, 10 October 2026, 23:29
  [step 4] get_current_time({}) -> Saturday, 10 October 2026, 23:29
  [step 5] get_current_time({}) -> Saturday, 10 October 2026, 23:29
Cue: Sorry, I could not finish that within the step limit.
```

| Question | What happened |
|---|---|
| Time **and** currency | Two tools requested in **one** step (parallel tool calls) |
| Order #4821 | One tool, one step |
| Order #9999 | The tool raised an error; it went back to the model as a message, and nothing crashed |
| What is Python? | No tool needed: the first reply was the final answer |
| Loop forever | The model kept asking; `MAX_STEPS` stopped it after 5 steps |

### Example 5: Cue Chat with Tools

This combines the chat loop from Lesson 4.3 with the tool loop.

Create `chat_tools.py`:

```python
from langchain.messages import ToolMessage
from langchain_core.messages.utils import convert_to_messages

from config import get_llm
from tools import TOOLS

SYSTEM_PROMPT = "You are Cue, a helpful AI assistant. Use tools when they help. Keep answers short."
MAX_STEPS = 5
EXIT_WORDS = ("exit", "quit", "bye", "/exit")

tools_by_name = {t.name: t for t in TOOLS}
llm_with_tools = get_llm().bind_tools(TOOLS)


def run_tool(call: dict) -> ToolMessage:
    tool = tools_by_name.get(call["name"])
    if tool is None:
        return ToolMessage(f"Error: unknown tool '{call['name']}'.", tool_call_id=call["id"], status="error")
    try:
        return tool.invoke(call)
    except Exception as error:
        return ToolMessage(f"Error: {error}", tool_call_id=call["id"], status="error")


def answer(history: list) -> str:
    """Run the tool loop. New messages are appended to history. Raises if the model call fails."""
    for _ in range(MAX_STEPS):
        reply = llm_with_tools.invoke(history)
        history.append(reply)
        if not reply.tool_calls:
            return reply.text
        for call in reply.tool_calls:
            print(f"  [using tool: {call['name']}]")
            history.append(run_tool(call))
    return "Sorry, I could not finish that within the step limit."


history = [{"role": "system", "content": SYSTEM_PROMPT}]
print("Welcome to Cue Chat with tools! Try: 'What time is it?' or 'Convert 50 USD to PKR'. Type 'exit' to quit.")

while True:
    try:
        question = input("You: ").strip()
    except (KeyboardInterrupt, EOFError):
        print("\nGoodbye!")
        break

    if not question:
        continue
    if question.lower() in EXIT_WORDS:
        print("Goodbye!")
        break
    if question.lower() == "/history":
        for message in convert_to_messages(history):
            calls = ", ".join(f"asks for {c['name']}" for c in getattr(message, "tool_calls", []))
            print(f"  [{message.type}] {(message.text or calls)[:70]}")
        continue

    turn_start = len(history)  # remember where this turn begins
    history.append({"role": "user", "content": question})
    try:
        print(f"Cue: {answer(history)}")
    except Exception as error:
        del history[turn_start:]  # remove EVERYTHING this turn added: question, tool calls, results
        print(f"Cue: Sorry, something went wrong ({type(error).__name__}). Please try again.")
```

Tested session (the final wording depends on your model):

```text
Welcome to Cue Chat with tools! Try: 'What time is it?' or 'Convert 50 USD to PKR'. Type 'exit' to quit.
You: What time is it?
  [using tool: get_current_time]
Cue: Here is what I found: Saturday, 10 October 2026, 23:29 
You: Convert 50 USD to PKR
  [using tool: convert_currency]
Cue: Here is what I found: 50.00 USD = 14,000.00 PKR 
You: /history
  [system] You are Cue, a helpful AI assistant. Use tools when they help. Keep an
  [human] What time is it?
  [ai] asks for get_current_time
  [tool] Saturday, 10 October 2026, 23:29
  [ai] Here is what I found: Saturday, 10 October 2026, 23:29 
  [human] Convert 50 USD to PKR
  [ai] asks for convert_currency
  [tool] 50.00 USD = 14,000.00 PKR
  [ai] Here is what I found: 50.00 USD = 14,000.00 PKR 
You: exit
Goodbye!
```

| Part | Why |
|---|---|
| `answer(history)` | Runs the tool loop and appends every message to the real history |
| `turn_start = len(history)` and `del history[turn_start:]` | If anything fails, remove **all** messages from this turn, not just the question |
| `/history` shows "asks for ..." | Tool-request messages have empty text, so the tool names are shown instead |

**What to notice in `/history`:** one question created **four** messages: the question, the model's tool request, the tool result, and the final answer. This is why Lesson 4.3's single `history.pop()` is no longer enough.

**Streaming and tools:** tool calls can be streamed too. They arrive as `tool_call_chunks`, and joining chunks with `+` (Lesson 4.4) builds the complete `tool_calls`. This lesson uses `invoke` to keep the loop easy to follow.

| Test | Result |

## Key Takeaways

1. **Tool calling** lets the model **request** actions; **your code** runs them and returns the results.
2. **`@tool`** builds a tool from a function: the name, the docstring description, and type hints become the schema. Use **`parse_docstring=True`** to send argument descriptions.
3. **`bind_tools`** tells the model which tools exist. A tool request arrives as **`reply.tool_calls`**, each with a `name`, `args`, and `id`.
4. **`tool.invoke(call)`** returns a **`ToolMessage`** whose `tool_call_id` links the result to the request.
5. Run tools in a **loop** until the model answers without tool calls, and **cap the steps**.
6. Handle **unknown tools and tool errors** as messages, and **roll back the whole turn** if a model call fails.
