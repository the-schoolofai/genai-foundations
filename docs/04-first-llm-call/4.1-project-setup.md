## 2. Why Provider-Agnostic?

In September 2026 alone, more than 20 new models were released by over a dozen providers. The best model for your app **will change**, often within months.

| Hard-wired app | Provider-agnostic app |
|---|---|
| Model name and SDK written into the code | Model chosen in a config file |
| Switching provider means rewriting code | Switching provider means changing **one line** in `.env` |
| Testing locally and in the cloud needs two code paths | Same code for a local Ollama model and a cloud model |

LangChain's **`init_chat_model`** makes this possible: you give it a `"provider:model"` string, and it creates the right chat model class for you.

> **Mental Model: The Universal Power Adapter**
> Your app is a laptop. Each provider (Ollama, Google, OpenAI, Anthropic) is a different country's socket. `init_chat_model` is the universal adapter: the laptop never changes; you just pick the socket.

## 4. Step-by-Step Setup

Skip any step you completed in Lesson 1.2.

### Step 1: Install uv

**macOS / Linux**
```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

**Windows (PowerShell)**
```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

```bash
uv --version
```

### Step 2: Create the Project

```bash
uv init cue-chat
cd cue-chat
```

`uv init` creates `pyproject.toml`, `.python-version`, `main.py`, `README.md`, a Git repository, and a `.gitignore`.

### Step 3: Add the Packages

```bash
uv add "langchain[ollama,google-genai]" python-dotenv
```

| Package | Purpose |
|---|---|
| `langchain` | The framework, including `init_chat_model` |
| `[ollama]` | Installs `langchain-ollama` for local models |
| `[google-genai]` | Installs `langchain-google-genai` for Gemini |
| `python-dotenv` | Loads settings from `.env` |

The `langchain[...]` "extras" syntax is how the LangChain docs install provider integrations. Other extras include `openai`, `anthropic`, `groq`, `mistralai`, `deepseek`, and `xai`. Add one later with, for example, `uv add "langchain[anthropic]"`.

### Step 4: Pull a Local Model

```bash
ollama pull gemma3:1b
```

`gemma3:1b` is a small model (about 0.8 GB) that runs on almost any laptop, which makes it ideal for development and testing.

### Step 5: Protect Your Secrets

`uv init` creates a `.gitignore`, but it does **not** include `.env`. Add it:

```bash
echo ".env" >> .gitignore
```

Check that Git now ignores it:

```bash
git check-ignore .env
```

If this prints `.env`, your secrets are protected.

## 5. The `.env` File

Create `.env`:

```dotenv
TEMPERATURE=0.7

# Ollama (local)
MODEL_NAME=ollama:gemma3:1b
API_KEY=

# Gemini (cloud)
# MODEL_NAME=google_genai:gemini-3.5-flash-lite
# API_KEY=your-gemini-key
```

To switch to Gemini, comment out the two Ollama lines and uncomment the two Gemini lines. **No code changes.**

### The `provider:model` Format

```text
ollama:gemma3:1b
└─┬──┘ └───┬───┘
provider   model name (can contain its own colon)
```

LangChain splits on the **first** colon, so `ollama:gemma3:1b` correctly means provider `ollama`, model `gemma3:1b`.

| Provider string | Package | Example `MODEL_NAME` |
|---|---|---|
| `ollama` | `langchain-ollama` | `ollama:gemma3:1b` |
| `google_genai` | `langchain-google-genai` | `google_genai:gemini-3.5-flash-lite` |
| `openai` | `langchain-openai` | `openai:<model-id>` |
| `anthropic` | `langchain-anthropic` | `anthropic:claude-sonnet-5-5` |
| `groq`, `mistralai`, `deepseek`, `xai`, `openrouter`, ... | Matching `langchain-...` package | `<provider>:<model-id>` |

**Always include the provider prefix.** LangChain can guess some providers from a bare name, but the guess can be wrong: a bare `gemini-...` name currently maps to `google_vertexai` (Google Cloud), not `google_genai` (the Gemini API key you get from Google AI Studio). The docs also recommend **pinned model IDs** over moving aliases, so behaviour doesn't change unexpectedly.

### The `.env.example` File

Teammates need to know which settings exist, without seeing your keys. Create `.env.example` with the same content as `.env`, but **no real keys**, and commit it. New developers copy it:

```bash
cp .env.example .env
```

> **Mental Model: The Form and the Filled-In Form**
> `.env.example` is the blank form everyone can see. `.env` is your filled-in copy with private details, kept in your own drawer.

## 6. `config.py`: One Place That Creates the Model

Every script in Cue Chat will get its model from here, so provider details live in exactly one file (the same **system approach** as `llm.py` in Lesson 1.3).

Create `config.py`:

```python
import os

from dotenv import load_dotenv
from langchain.chat_models import init_chat_model
from langchain_core.language_models import BaseChatModel

load_dotenv()


def get_llm(**overrides) -> BaseChatModel:
    """Create the chat model described in .env. Keyword arguments override .env values."""
    model_name = os.getenv("MODEL_NAME", "").strip()
    if ":" not in model_name:
        raise ValueError("Set MODEL_NAME in .env as 'provider:model', for example 'ollama:gemma3:1b'.")

    settings = {"temperature": float(os.getenv("TEMPERATURE", "0.7"))}

    api_key = os.getenv("API_KEY", "").strip()
    if api_key:
        settings["api_key"] = api_key

    settings.update(overrides)
    return init_chat_model(model_name, **settings)
```

| Line | Why |
|---|---|
| `load_dotenv()` | Loads `.env` into environment variables |
| `if ":" not in model_name` | Fails early with a helpful message if the prefix is missing |
| `float(os.getenv("TEMPERATURE", "0.7"))` | `.env` values are always strings; convert, and use a default if missing |
| `if api_key:` | Only passes a key when one is set: Ollama needs none, and an empty key would break cloud providers |
| `**overrides` | Lets a script change settings, for example `get_llm(temperature=0)` for a classifier |
| `-> BaseChatModel` | Every LangChain chat model shares this type, so the rest of your code works with any provider |

**Alternative for API keys:** each provider also reads its own standard environment variable, for example `GOOGLE_API_KEY` (or `GEMINI_API_KEY`) for Gemini, `OPENAI_API_KEY`, and `ANTHROPIC_API_KEY`. A single `API_KEY` works well while you switch between one provider at a time; provider-specific names are better when an app uses **several** providers at once.

## 7. `check_setup.py`: Verify Your Environment

Before calling a model, confirm that everything is installed and configured, **without printing your full key**.

Create `check_setup.py`:

```python
import os
import sys
from importlib.metadata import PackageNotFoundError, version

from dotenv import load_dotenv

load_dotenv()

print(f"Python:        {sys.version.split()[0]}")
for package in ["langchain", "langchain-core", "langchain-ollama", "langchain-google-genai", "python-dotenv"]:
    try:
        print(f"{package:<23}{version(package)}")
    except PackageNotFoundError:
        print(f"{package:<23}NOT INSTALLED")

model_name = os.getenv("MODEL_NAME", "")
api_key = os.getenv("API_KEY", "")
provider = model_name.split(":", 1)[0] if ":" in model_name else "(missing)"

print(f"\nMODEL_NAME:    {model_name or '(missing)'}")
print(f"Provider:      {provider}")
print(f"TEMPERATURE:   {os.getenv('TEMPERATURE', '(default 0.7)')}")
print(f"API_KEY:       {api_key[:4] + '...' + api_key[-2:] if len(api_key) > 8 else '(not set)'}")
```

```bash
uv run check_setup.py
```

## 8. `smoke_test.py`: Your First Call

A **smoke test** is the smallest check that proves the whole chain works: settings, package, model, and response.

Create `smoke_test.py`:

```python
import time

from config import get_llm

llm = get_llm()

start = time.perf_counter()
response = llm.invoke("In one short sentence, welcome a new AI engineering student.")
seconds = time.perf_counter() - start

print("Reply:   ", response.text)
print("Model:   ", response.response_metadata.get("model_name"))
print("Provider:", response.response_metadata.get("model_provider"))
print("Tokens:  ", response.usage_metadata)
print(f"Time:     {seconds:.2f} s")
```

Make sure Ollama is running, then:

```bash
uv run smoke_test.py
```

Example output (the reply text, tokens, and time will differ):

```text
Reply:    Welcome to AI engineering, where you build the future one prompt at a time!
Model:    gemma3:1b
Provider: ollama
Tokens:   {'input_tokens': 21, 'output_tokens': 17, 'total_tokens': 38}
Time:     1.84 s
```

### Now Switch to Gemini

1. Get a free API key from Google AI Studio.
2. In `.env`, comment out the Ollama lines and uncomment the Gemini lines, adding your key.
3. Run the **same** command:

```bash
uv run smoke_test.py
```

`Provider` now shows `google_genai`, and the model name changes. Not one line of Python changed.

## 9. Troubleshooting

These are the real errors you will see, and what they mean:

| Error | Cause | Fix |
|---|---|---|
| `ValueError: Set MODEL_NAME in .env as 'provider:model'...` | `MODEL_NAME` is missing or has no provider prefix | Use `ollama:gemma3:1b` or `google_genai:gemini-3.5-flash-lite` |
| `httpx.ConnectError: [Errno 111] Connection refused` | Ollama is not running | Start the Ollama app (or `ollama serve`) |
| `ValidationError ... API key required for Gemini Developer API` | Gemini selected but no key set | Add `API_KEY` (or `GOOGLE_API_KEY`) to `.env` |
| `ImportError: Initializing ChatAnthropic requires the langchain-anthropic package` | Provider package not installed | `uv add "langchain[anthropic]"` |
| `ValueError: could not convert string to float: 'hot'` | Invalid `TEMPERATURE` in `.env` | Use a number such as `0.7` |
| Model not found (Ollama) | The model was never pulled | `ollama pull gemma3:1b` |

## Key Takeaways

1. **uv** creates the project and manages packages; install providers with `uv add "langchain[ollama,google-genai]"`.
2. Keep settings in **`.env`**, add `.env` to **`.gitignore`** (uv doesn't by default), and share a key-free **`.env.example`**.
3. **`init_chat_model("provider:model")`** creates the right chat model for any provider; always include the prefix.
4. Put model creation in **one function** (`get_llm()` in `config.py`), with validation and safe defaults.
5. Run **`check_setup.py`** and a **smoke test** before building features; never print full API keys.
6. Switching between local and cloud models is a **one-line `.env` change**.

**Practice:** Add a third provider. Run `uv add "langchain[groq]"` (or another provider you have a key for), add its lines to `.env` and `.env.example`, and run `smoke_test.py` on all three providers. Record each one's reply time and token counts in a small table.
