## Module 3: Prompt Engineering

### 3.5 Structured Outputs and Prompt Templates

---

## 1. Two Problems in Real Applications

| Problem | Example | Solution |
|---|---|---|
| **The output must be read by code** | Your app needs `category`, `priority`, and `order_number`, not a paragraph | **Structured output** |
| **The same prompt runs with different data** | One support prompt, thousands of tickets | **Prompt templates** |

> **Mental Model: The Form and the Letter Template**
> **Structured output** is a form the model must fill in: fixed boxes, allowed values, nothing extra. A **prompt template** is a letter template with blanks like `{customer_name}`: written once, filled in for every request.

---

## 2. Three Levels of Output Control

| Level | How | Reliability |
|---|---|---|
| 1. Ask in the prompt | "Reply in JSON with keys category and priority." | Low: the model may add text, miss keys, or break JSON |
| 2. Output tags | `<category>...</category>` (Lesson 3.2) | Medium: easy to parse, but not validated |
| 3. **Schema-enforced structured output** | Send a Pydantic schema; the provider constrains the output to match it | **High**: valid JSON with the right fields and types |

In production, use **level 3** whenever code depends on the result.

---

## 3. Designing a Good Schema

A schema is also a **prompt**. Field names, types, and descriptions all guide the model.

```python
from typing import Literal

from pydantic import BaseModel, Field


class TicketAnalysis(BaseModel):
    """Analysis of one ShopPK customer support ticket."""

    category: Literal["billing", "delivery", "technical", "account", "other"] = Field(
        description="Main topic. If money is involved, use billing."
    )
    priority: Literal["low", "medium", "high"] = Field(
        description="high if the customer lost money or cannot use the product"
    )
    order_number: str | None = Field(
        default=None, description="Order number such as #4821, or null if not mentioned"
    )
    summary: str = Field(description="One sentence, under 20 words")
```

| Design rule | Why |
|---|---|
| Use `Literal[...]` for fixed choices | The model can only pick allowed values |
| Write a `description` for every field | Descriptions act as instructions for each field |
| Use `None` for optional information | Gives the model a safe way to say "not mentioned" instead of inventing data |
| Keep field names clear (`order_number`, not `on`) | Names are part of the prompt |
| Keep the schema small | Fewer fields means fewer mistakes |

> **Mental Model: The Schema Is the Job Description for the Answer**
> The system prompt describes the job. The schema describes **exactly what to hand back**. Write both with the same care.

---

## 4. Schema Types in LangChain

| Type | Returns | Validation | Use when |
|---|---|---|---|
| **Pydantic `BaseModel`** | A Pydantic object | Automatic | Most production code (recommended) |
| **`TypedDict`** | A Python dictionary | Manual | You just want a dictionary |
| **JSON Schema (dict)** | A Python dictionary | Manual | Schemas shared with other languages or services |

The `method` parameter controls how the structure is enforced:

| `method` | How it works |
|---|---|
| `"json_schema"` | Uses the provider's native structured output feature (default for `ChatOllama`) |
| `"function_calling"` | Forces a tool call that follows the schema |
| `"json_mode"` | Guarantees valid JSON only; you must describe the schema in the prompt |

## 5. Prompt Templates

A **prompt template** is a prompt with **variables** that are filled in at run time.

```python
from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a support assistant for {store}. Today is {today}."),
    ("human", "<ticket>{ticket}</ticket>"),
])
```

| Feature | What it does |
|---|---|
| `{variable}` | A blank filled in at run time |
| `.invoke({...})` | Fills the blanks and returns ready-to-send messages |
| `.partial(...)` | Fills some blanks once (store name, date), leaving the rest for later |
| `MessagesPlaceholder("history")` | A slot for a list of messages, such as chat history (Lesson 2.2) |
| `prompt \| model` | Connects the template to a model, so one call does both |

**Watch out for curly braces:** templates use `{name}` for variables. To include literal braces (for example a JSON example in the prompt), double them: `{{"key": "value"}}`.

### Why Templates Matter in Production

| Without templates | With templates |
|---|---|
| Prompts built with string `+` everywhere | One clear template per task |
| Easy to forget a variable or break the layout | Missing variables raise an error |
| Prompt text hidden in code | Prompt text can live in its own file and be reviewed and versioned |

> **Mental Model: Prompts Are Assets, Not Strings**
> Treat prompts like images or config files: stored in their own files, named, versioned (`support_v1`, `support_v2`), and reviewed before changes go live.

## 7. OpenAI SDK Example

### Example 1: Structured Output with Validation

Lesson 1.3 introduced `.parse()`. Here you use a richer schema and handle failures properly.

Create `openai_structured.py`:

```python
from typing import Literal

from pydantic import BaseModel, Field

from llm import get_client


class TicketAnalysis(BaseModel):
    category: Literal["billing", "delivery", "technical", "account", "other"] = Field(
        description="Main topic. If money is involved, use billing."
    )
    priority: Literal["low", "medium", "high"] = Field(
        description="high if the customer lost money or cannot use the product"
    )
    order_number: str | None = Field(default=None, description="Order number, or null if not mentioned")
    summary: str = Field(description="One sentence, under 20 words")


client, model = get_client()

ticket = "Order #4821: I was charged twice and the parcel still hasn't arrived. Please fix this today."

completion = client.chat.completions.parse(
    model=model,
    messages=[
        {"role": "system", "content": "Analyze the ShopPK support ticket."},
        {"role": "user", "content": f"<ticket>{ticket}</ticket>"},
    ],
    response_format=TicketAnalysis,
    temperature=0,
)

message = completion.choices[0].message
if message.parsed:
    result = message.parsed
    print(result.model_dump_json(indent=2))
    if result.priority == "high":
        print("\nAction: send to the urgent queue")
elif message.refusal:
    print("Model refused:", message.refusal)
```

| Code | Meaning |
|---|---|
| `response_format=TicketAnalysis` | The schema is sent to the provider, which constrains the output |
| `message.parsed` | A validated `TicketAnalysis` object, or `None` |
| `message.refusal` | Set if the model declined the request (mainly OpenAI models) |
| `model_dump_json(indent=2)` | Turns the object into readable JSON |

**Expected result:** `category` is `billing` (money involved), `priority` is `high`, and `order_number` is `#4821`.

## 8. LangChain Examples

### Example 2: `with_structured_output` with a Nested Schema

Create `lc_structured.py`:

```python
from typing import Literal

from langchain_ollama import ChatOllama
from pydantic import BaseModel, Field


class Issue(BaseModel):
    problem: str = Field(description="One problem the customer reports, in a few words")
    category: Literal["billing", "delivery", "technical", "account", "other"]


class TicketReport(BaseModel):
    """All issues in one customer ticket."""

    customer_name: str | None = Field(default=None, description="Customer's name, or null if not given")
    issues: list[Issue] = Field(description="Every separate problem in the ticket")
    sentiment: Literal["positive", "neutral", "negative"]
    needs_human: bool = Field(description="True if the issue cannot be solved by a standard reply")


llm = ChatOllama(model="gemma4:e2b", temperature=0)
structured_llm = llm.with_structured_output(TicketReport)

ticket = (
    "Hi, this is Hira. My order came late, the app keeps logging me out, "
    "and I was charged a delivery fee on a free-shipping order. Very disappointed."
)

report = structured_llm.invoke(f"Analyze this ShopPK ticket:\n<ticket>{ticket}</ticket>")

print("Customer: ", report.customer_name)
print("Sentiment:", report.sentiment)
print("Human?    ", report.needs_human)
for issue in report.issues:
    print(f"  - [{issue.category}] {issue.problem}")
```

**What to notice:** one ticket contains **three** problems (delivery, technical, billing). A nested `list[Issue]` captures all of them as separate, typed items.

### Example 3: TypedDict and `include_raw` for Safe Error Handling

`include_raw=True` returns the raw message, the parsed result, and any parsing error, so your app never crashes on a bad response.

Create `lc_structured_raw.py`:

```python
from typing import Literal

from langchain_ollama import ChatOllama
from typing_extensions import Annotated, TypedDict


class ReviewRating(TypedDict):
    """Sentiment and rating for a product review."""

    sentiment: Annotated[Literal["positive", "neutral", "negative"], ..., "Overall sentiment"]
    rating: Annotated[int, ..., "Estimated star rating from 1 to 5"]


llm = ChatOllama(model="gemma4:e2b", temperature=0)
rater = llm.with_structured_output(ReviewRating, include_raw=True)

result = rater.invoke("Review: 'Good quality bag, but the zip broke after a month.'")

if result["parsing_error"]:
    print("Could not parse:", result["parsing_error"])
else:
    parsed = result["parsed"]
    if not 1 <= parsed["rating"] <= 5:
        print("Invalid rating:", parsed["rating"])
    else:
        print(parsed)

print("Tokens:", result["raw"].usage_metadata)
```

| Key | Contains |
|---|---|
| `result["parsed"]` | The dictionary (or `None` if parsing failed) |
| `result["parsing_error"]` | The error, or `None` |
| `result["raw"]` | The original `AIMessage`, including token usage (Lesson 2.4) |

`TypedDict` results are **not validated automatically**, so the code checks the rating range itself. With Pydantic you would use `Field(ge=1, le=5)` instead.

### Example 4: Your First Prompt Template

Create `lc_template.py`:

```python
from datetime import date

from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_ollama import ChatOllama

prompt = ChatPromptTemplate.from_messages([
    (
        "system",
        "You are a support assistant for {store}. Today is {today}.\n"
        "Answer only from this policy:\n<policy>\n{policy}\n</policy>\n"
        "Keep replies under 60 words.",
    ),
    MessagesPlaceholder("history", optional=True),
    ("human", "<customer_message>{message}</customer_message>"),
])

support_prompt = prompt.partial(
    store="ShopPK",
    today=date.today().strftime("%d %B %Y"),
    policy="Electronics: 7-day refund window, then 1-year warranty repair.",
)

print("Still needed:", support_prompt.input_variables)

filled = support_prompt.invoke({"message": "My earphones broke after 3 days. Refund please."})
for message in filled.to_messages():
    print(f"[{message.type}] {message.content}\n")

llm = ChatOllama(model="gemma4:e2b", temperature=0.3)
chain = support_prompt | llm

print("REPLY:", chain.invoke({"message": "My earphones broke after 3 days. Refund please."}).content)
```

| Code | Meaning |
|---|---|
| `{store}`, `{today}`, `{policy}`, `{message}` | Template variables |
| `.partial(...)` | Fills the fixed values once; only `message` remains |
| `MessagesPlaceholder("history", optional=True)` | Chat history can be added later, or left out |
| `support_prompt \| llm` | A **chain**: fill the template, then call the model |

**What to notice:** `Still needed: ['message']`. The app now only supplies the customer's message; everything else is fixed in one place.

### Example 5: Template + Structured Output Pipeline

Combine both ideas: a template fills the prompt, and the model returns a typed object for **every** ticket.

Create `lc_pipeline.py`:

```python
from typing import Literal

from langchain_core.prompts import ChatPromptTemplate
from langchain_ollama import ChatOllama
from pydantic import BaseModel, Field


class Triage(BaseModel):
    category: Literal["billing", "delivery", "technical", "account", "other"] = Field(
        description="If money is involved, use billing"
    )
    priority: Literal["low", "medium", "high"]
    reply: str = Field(description="A polite reply to the customer, under 40 words")


prompt = ChatPromptTemplate.from_messages([
    ("system", "You triage support tickets for {store}. Be accurate and concise."),
    ("human", "<ticket>{ticket}</ticket>"),
]).partial(store="ShopPK")

llm = ChatOllama(model="gemma4:e2b", temperature=0)
triage_chain = prompt | llm.with_structured_output(Triage)

tickets = [
    "I was charged twice for order #5521.",
    "The app crashes every time I open my cart.",
    "Do you sell gift cards?",
]

results = triage_chain.batch([{"ticket": ticket} for ticket in tickets])

print(f"{'CATEGORY':<10} {'PRIORITY':<8} TICKET")
for ticket, result in zip(tickets, results):
    print(f"{result.category:<10} {result.priority:<8} {ticket}")

print("\nAs data rows:", [result.model_dump() for result in results][0])
```

**What to notice:** the output is a list of `Triage` objects, ready to sort, save to a database, or show on a dashboard. `model_dump()` converts each one into a plain dictionary.

### Example 6: Prompts in Files, with Versions

Keep prompt text out of Python code so it can be reviewed, compared, and versioned.

Create `prompts/support_v1.md`:

```text
You are a support assistant for {store}.
Answer only from the policy below. Keep replies under 60 words.

<policy>
{policy}
</policy>
```

Create `prompts/support_v2.md`:

```text
# Identity
You are a support assistant for {store}, an online store in Pakistan.

# Instructions
- Answer only from the policy. If it is not covered, say a human agent will follow up within 24 hours.
- Reply with a greeting, the answer, and one clear next step.
- Keep replies under 60 words, warm and professional.

# Context
<policy>
{policy}
</policy>
```

Create `lc_prompt_files.py`:

```python
from pathlib import Path

from langchain_core.prompts import ChatPromptTemplate
from langchain_ollama import ChatOllama

PROMPTS_DIR = Path("prompts")
POLICY = "Electronics: 7-day refund window, then 1-year warranty repair. Delivery: 2-4 working days."


def load_prompt(name: str) -> ChatPromptTemplate:
    system_text = (PROMPTS_DIR / f"{name}.md").read_text(encoding="utf-8")
    return ChatPromptTemplate.from_messages([
        ("system", system_text),
        ("human", "<customer_message>{message}</customer_message>"),
    ]).partial(store="ShopPK", policy=POLICY)


llm = ChatOllama(model="gemma4:e2b", temperature=0)
message = "Can I pay in instalments?"

for version in ["support_v1", "support_v2"]:
    chain = load_prompt(version) | llm
    print(f"--- {version} ---\n{chain.invoke({'message': message}).content}\n")
```

| Code | Meaning |
|---|---|
| `prompts/support_v1.md`, `support_v2.md` | Prompt versions stored as files |
| `load_prompt(name)` | Reads a prompt file and turns it into a template |
| Loop over versions | Compare versions on the same input (Lesson 3.7 makes this systematic) |

**What to notice:** instalments are not in the policy. Version 2 has a rule for missing information, so it should hand the question to a human. In a team, these files are tracked in Git, so every prompt change is reviewed like a code change.

## 9. Checklist

| Check | Done |
|---|---|
| Code that depends on model output uses schema-enforced structured output | |
| Every field has a clear name, type, and description | |
| Fixed choices use `Literal`; optional facts use `None` | |
| Parsing errors are handled (`include_raw=True` or a `parsed` check) | |
| Prompts use templates with variables, not string concatenation | |
| Fixed values are set once with `.partial()` | |
| Literal braces in templates are doubled: `{{ }}` | |
| Prompt text lives in versioned files | |

---

## Key Takeaways

1. **Structured output** turns model answers into typed data your code can trust; use schema enforcement, not just "reply in JSON".
2. A **schema is part of the prompt**: names, types, `Literal` choices, and descriptions all guide the model.
3. In LangChain, use **`with_structured_output`** with Pydantic (validated), `TypedDict`, or JSON Schema, and `include_raw=True` for safe error handling.
4. **Prompt templates** (`ChatPromptTemplate`) separate fixed prompt text from changing data; use `.partial()` for fixed values and `MessagesPlaceholder` for history.
5. **`prompt | llm.with_structured_output(Schema)`** is a complete, reusable pipeline that works on one ticket or thousands with `batch`.
6. Treat prompts as **versioned assets** stored in files.
