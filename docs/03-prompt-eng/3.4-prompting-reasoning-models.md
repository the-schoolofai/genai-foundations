## Module 3: Prompt Engineering

### 3.4 Prompting Reasoning Models

---

## 1. Two Kinds of Models

| | Instant (non-reasoning) model | Reasoning model |
|---|---|---|
| How it answers | Starts writing the answer immediately | **Thinks first** (generates hidden reasoning tokens), then answers |
| Strong at | Chat, summaries, extraction, classification | Math, logic, multi-step rules, code, planning |
| Speed and cost | Fast and cheaper | Slower; reasoning tokens are billed as output |
| Examples | Small local models with thinking off, fast "mini" tiers | OpenAI GPT-5.5+, Claude with thinking, DeepSeek-R1, Gemma 4 / Qwen with thinking on |

Many 2026 models are **hybrid**: the same model can think or not, and you control **how much** it thinks.

> **Mental Model: Mental Maths vs Scratch Paper**
> An instant model answers like someone doing mental maths: fast, but easy to slip. A reasoning model uses scratch paper first: slower, but far more reliable on multi-step problems. Your job is to decide **when the scratch paper is worth the time and money**.

---

## 2. A Short History of Reasoning

| Year | Milestone | Why it matters |
|---|---|---|
| 2022 | **Chain-of-thought prompting** research | Showing or asking for step-by-step reasoning ("Let's think step by step") improved maths and logic answers |
| 2024 | OpenAI o1 | Reasoning **built into the model**, trained to think before answering |
| 2025 | DeepSeek-R1 | Open-weight reasoning models; runnable locally |
| 2025–2026 | Hybrid models with **effort control** | One model, adjustable thinking: OpenAI `reasoning_effort`, Claude adaptive thinking with `effort`, Ollama `think` |

The big shift: with older models, **you** had to make the model reason through the prompt. With reasoning models, the model already does it, and old prompting habits can **hurt**.

---

## 3. Prompting Instant Models: Chain-of-Thought

For instant models, asking for step-by-step reasoning still helps on multi-step problems.

```text
Work through the problem step by step. Then give only the final amount inside <answer> tags.
```

| Technique | Why |
|---|---|
| Ask for steps before the answer | The model "writes its scratch paper" into the output |
| Put the final answer in tags | Your code can extract the answer and ignore the steps (Lesson 3.2) |
| Use temperature 0 | Reasoning should be consistent (Lesson 2.3) |

---

## 4. Prompting Reasoning Models: Different Rules

Guidance from OpenAI and Anthropic for reasoning models:

| Do | Avoid |
|---|---|
| Keep prompts **simple and direct** | Long, hand-written step-by-step plans |
| Give the **goal, constraints, and success criteria** | "Think step by step" (it already does; this can even hurt) |
| Use **structure** (Markdown, XML) to separate rules and data | Mixing instructions and data |
| Try **zero-shot first**; add examples only if needed | Many examples that conflict with instructions |
| Ask it to **verify** its answer against clear criteria | Asking it to print its full hidden reasoning |
| Control thinking with the **effort setting** | Controlling thinking with prompt tricks |

**Prefer general guidance over prescribed steps.** Anthropic notes that a prompt like "think thoroughly" often produces better reasoning than a hand-written step-by-step plan, because the model's own reasoning frequently exceeds what a person would prescribe. Use numbered steps only when the **order** of steps truly matters.

**Don't ask for visible reasoning in tags.** On some current Claude models (including Opus 5.5 and Sonnet 5.5), prompts asking the model to write its reasoning inside `<thinking>` tags may be declined. Use the thinking feature and effort setting instead.

> **Mental Model: Brief the Expert, Don't Micromanage**
> An instant model is a trainee: give step-by-step instructions. A reasoning model is an expert: tell them the goal, the rules, and what "done" looks like, and let them work.

---

## 5. Controlling How Much the Model Thinks

| Platform | Setting | Values |
|---|---|---|
| OpenAI API | `reasoning_effort` | `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max` (varies by model) |
| Anthropic API | `thinking={"type": "adaptive"}` with `effort` | Effort levels such as `low`, `medium`, `high` |
| Ollama | `think` | `True` / `False`, or levels such as `"low"`, `"medium"`, `"high"` for models that support them (for example gpt-oss) |
| LangChain (cloud models) | `reasoning_effort` (standard parameter) | Translated to each provider's format |
| LangChain `ChatOllama` | `reasoning` | `True`, `False`, or a level string |

### When to Turn Reasoning Up or Down

| Task | Reasoning | Why |
|---|---|---|
| Classification, extraction, simple chat | Off or low | Fast and cheap; thinking adds little |
| Summaries, rewriting | Off or low | Language tasks, not logic tasks |
| Policy decisions with several rules and dates | Medium | Multiple conditions must be checked |
| Maths, calculations, code, planning | High | Multi-step logic, where errors are costly |

Reasoning tokens count as **output tokens**, so higher effort means higher cost and latency (Lesson 2.4).

## 7. OpenAI SDK Example

### Example 1: Answer Only vs Chain-of-Thought

This uses chain-of-thought prompting, which works with **any** model through `llm.py`.

Create `cot_compare.py`:

```python
import re

from llm import get_client

client, model = get_client()

PROBLEM = (
    "Ali ordered 3 shirts at Rs 2,400 each and 1 pair of shoes at Rs 6,500. "
    "A 10% discount was applied to all items. Shipping of Rs 300 is non-refundable. "
    "Ali returns 1 shirt. How much money should ShopPK refund?"
)

PROMPTS = {
    "Answer only": f"{PROBLEM}\nReply with the amount only.",
    "Step by step": f"{PROBLEM}\nWork through it step by step. Then give only the final amount in <answer> tags.",
}

for name, prompt in PROMPTS.items():
    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
        temperature=0,
        max_tokens=400,
    )
    text = response.choices[0].message.content
    match = re.search(r"<answer>(.*?)</answer>", text, re.DOTALL)
    final = match.group(1).strip() if match else text.strip()
    print(f"{name:<13} -> {final}   (output tokens: {response.usage.completion_tokens})")
```

**What to notice:** "Answer only" is fast but more likely to say Rs 2,400. "Step by step" uses more tokens and is more likely to reach Rs 2,160. You pay for reasoning either way: in visible steps here, or in hidden reasoning tokens with a reasoning model.

With a reasoning model (for example `PROVIDER=openai`), replace the prompt with the plain problem and use `reasoning_effort="low"` or `"high"`. The reasoning-token count is in `response.usage.completion_tokens_details.reasoning_tokens`.

## 8. LangChain Examples

### Example 2: Turn On Thinking and Read the Reasoning

Create `lc_thinking.py`:

```python
from langchain_ollama import ChatOllama

llm = ChatOllama(model="gemma4:e2b", temperature=0, reasoning=True)

PROBLEM = (
    "Ali ordered 3 shirts at Rs 2,400 each and 1 pair of shoes at Rs 6,500. "
    "A 10% discount was applied to all items. Shipping of Rs 300 is non-refundable. "
    "Ali returns 1 shirt. How much money should ShopPK refund? Reply with the amount only."
)

response = llm.invoke(PROBLEM)

reasoning = [block["reasoning"] for block in response.content_blocks if block["type"] == "reasoning"]

print("THINKING:\n", " ".join(reasoning)[:800], "...\n")
print("ANSWER:", response.text)
```

| Code | Meaning |
|---|---|
| `reasoning=True` | Turns on the model's thinking mode in Ollama |
| `response.content_blocks` | LangChain's standard list of content parts: `reasoning` and `text` blocks |
| `response.text` | Only the final answer text, without the reasoning |

**What to notice:** the prompt says "amount only", yet the model thinks at length first. The thinking is kept **separate** from the answer, so your app can show only the answer and log the reasoning for debugging.

### Example 3: Thinking On vs Off, Measured

Create `lc_thinking_compare.py`:

```python
import time

from langchain_ollama import ChatOllama

PROBLEM = (
    "Ali ordered 3 shirts at Rs 2,400 each and 1 pair of shoes at Rs 6,500. "
    "A 10% discount was applied to all items. Shipping of Rs 300 is non-refundable. "
    "Ali returns 1 shirt. How much money should ShopPK refund? Reply with the amount only."
)

for reasoning in [False, True]:
    llm = ChatOllama(model="gemma4:e2b", temperature=0, reasoning=reasoning)

    start = time.perf_counter()
    response = llm.invoke(PROBLEM)
    seconds = time.perf_counter() - start

    correct = "2,160" in response.text or "2160" in response.text
    tokens = response.usage_metadata["output_tokens"]
    print(f"thinking={str(reasoning):<5} answer={response.text.strip():<12} correct={correct}  "
          f"output tokens={tokens}  time={seconds:.1f}s")
```

**What to notice:** thinking usually costs **more tokens and more time**, and is usually **more accurate** on multi-step maths. That is the trade-off you decide for every task. Run it a few times: small models are not perfectly consistent.

### Example 4: Stream the Thinking, Then the Answer

Users wait longer for reasoning models, so showing progress matters (Lesson 2.4).

Create `lc_thinking_stream.py`:

```python
from langchain_ollama import ChatOllama

llm = ChatOllama(model="gemma4:e2b", temperature=0, reasoning=True)

question = "Is 2,160 the correct refund if a Rs 2,400 shirt had a 10% discount? Answer yes or no with one reason."

shown_answer_header = False
print("[thinking] ", end="")

for chunk in llm.stream(question):
    for block in chunk.content_blocks:
        if block["type"] == "reasoning":
            print(".", end="", flush=True)  # show progress without printing every thought
        elif block["type"] == "text" and block["text"]:
            if not shown_answer_header:
                print("\n[answer] ", end="")
                shown_answer_header = True
            print(block["text"], end="", flush=True)
print()
```

**What to notice:** dots appear while the model thinks, then the answer streams. Many products show a "Thinking..." indicator in the same way.

### Example 5: Micromanaging vs Briefing the Expert

Compare a prescriptive prompt with a goal-and-criteria prompt on a **policy decision** with dates.

Create `lc_reasoning_prompt_style.py`:

```python
from langchain.messages import HumanMessage, SystemMessage
from langchain_ollama import ChatOllama

CASE = """<policy>
- Electronics: 7-day refund window from delivery, then a 1-year warranty repair.
- Other items: 14-day refund window from delivery.
</policy>

<case>
Today is 10 October 2026. Headphones were delivered on 1 October 2026.
They stopped working. The customer asks for a refund.
</case>"""

PRESCRIPTIVE = SystemMessage(
    "Step 1: Read the policy. Step 2: Read the case. Step 3: Think step by step. "
    "Step 4: Write your reasoning. Step 5: Decide. Step 6: Write the answer."
)

BRIEF = SystemMessage(
    "You decide ShopPK support cases using only the policy.\n"
    "Goal: choose exactly one outcome: REFUND, WARRANTY_REPAIR, or ESCALATE.\n"
    "Success criteria: the outcome follows the policy and the dates; the reason is one sentence.\n"
    "Before you finish, check your decision against the dates in the case.\n"
    "Format: <outcome>...</outcome><reason>...</reason>"
)

llm = ChatOllama(model="gemma4:e2b", temperature=0, reasoning=True)

for name, system in [("Prescriptive", PRESCRIPTIVE), ("Brief", BRIEF)]:
    response = llm.invoke([system, HumanMessage(CASE)])
    print(f"--- {name} ({response.usage_metadata['output_tokens']} output tokens) ---")
    print(response.text.strip(), "\n")
```

**Correct outcome:** `WARRANTY_REPAIR`. Nine days have passed since delivery, which is past the 7-day electronics refund window, but within the 1-year warranty.

**What to notice:** the brief prompt gives a clear goal, allowed outcomes, success criteria, a verification step, and a parseable format, without telling the model **how** to think. The prescriptive prompt often produces long visible reasoning in the answer and no consistent format.

### Example 6: Reasoning Effort with Cloud Models (Optional)

LangChain's standard `reasoning_effort` parameter works the same way across supported providers (OpenAI, Anthropic, Google, xAI, and others). It can be set when creating the model or **per request**.

Create `lc_reasoning_effort.py` (needs `uv add langchain-anthropic` and `ANTHROPIC_API_KEY` in `.env`):

```python
from dotenv import load_dotenv
from langchain.chat_models import init_chat_model

load_dotenv()

llm = init_chat_model("anthropic:claude-sonnet-5-5", max_tokens=2000)

classification = llm.invoke(
    "Label this ticket as billing, delivery, or technical: 'I was charged twice.' Label only.",
    reasoning_effort="low",
)

calculation = llm.invoke(
    "3 shirts at Rs 2,400 and shoes at Rs 6,500, 10% discount on all items, Rs 300 non-refundable "
    "shipping. One shirt is returned. What is the refund? Amount only.",
    reasoning_effort="high",
)

for name, response in [("low effort", classification), ("high effort", calculation)]:
    print(f"{name:<12} answer={response.text.strip():<10} output tokens={response.usage_metadata['output_tokens']}")
```

**What to notice:** one model, two effort levels: **low** for the simple label, **high** for the calculation. Matching effort to the task is how teams control reasoning cost in production.

## 9. Reasoning Prompt Checklist

| Check | Done |
|---|---|
| Decided whether the task needs reasoning at all | |
| Instant model + multi-step task: asked for steps, final answer in tags | |
| Reasoning model: removed "think step by step" and long step lists | |
| Gave the goal, constraints, allowed outputs, and success criteria | |
| Asked the model to verify its answer against clear criteria | |
| Set the effort level to match the task | |
| Kept reasoning separate from the answer shown to users | |
| Measured accuracy, tokens, and time with and without reasoning | |

---

## Key Takeaways

1. **Reasoning models think before answering**; instant models answer immediately. Many 2026 models can do both.
2. For **instant models**, chain-of-thought prompting ("step by step", final answer in tags) still helps on multi-step problems.
3. For **reasoning models**, keep prompts simple: give the goal, rules, and success criteria; don't prescribe how to think.
4. Control thinking with **effort settings** (`reasoning_effort`, `think`, `reasoning`), not prompt tricks.
5. Reasoning costs **tokens and time**: use it for maths, logic, rules, and code, not for simple labels or chat.
6. In LangChain, read thinking from **`content_blocks`** and the final answer from **`.text`**.

**Practice:** Create three tasks (a label, a summary, and a date-based policy decision). Run each with thinking off and on, record accuracy, output tokens, and time, and write a one-line rule for when your app should enable reasoning.
