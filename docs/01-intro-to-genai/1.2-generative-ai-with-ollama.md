## 1. What Is Local AI?

**Local AI means running a Generative AI model on your own computer instead of sending your data to a company's servers.**

> **Mental Model: Cooking at Home vs Ordering Out**
> **Cloud AI** is like ordering from a restaurant: you get powerful results fast, but you pay per order and your request leaves your house.
> **Local AI** is like cooking at home: it's free after setup, private, and works offline, but you are limited by the size of your kitchen (your RAM and GPU).

### Local AI vs Cloud AI

| | Local AI | Cloud AI |
|---|---|---|
| **Where it runs** | Your laptop or company server | Provider's data center |
| **Cost** | Free after download | Pay per token |
| **Privacy** | Data never leaves your machine | Data is sent to the provider |
| **Internet** | Works offline | Required |
| **Model size** | Limited by your hardware | Very large models available |
| **Best for** | Private data, prototyping, learning, offline apps | Highest quality, heavy workloads |

### Why the Industry Uses Local GenAI

- **Privacy and compliance:** Banks, hospitals, and government offices can't always send data to external servers.
- **Cost control:** No per-token bill during development and testing.
- **Offline and edge use:** Factories, field devices, and low-connectivity areas.
- **Prototyping:** Build and test locally, then switch to a larger cloud model for production.

## 2. Open-Weight Models: What Makes Local AI Possible

A model's **weights** are the numbers it learned during training. When a company publishes them, anyone can download and run the model. These are called **open-weight models**.

| Model family | Company |
|---|---|
| Gemma | Google DeepMind |
| Llama | Meta |
| Qwen | Alibaba |
| DeepSeek | DeepSeek |
| gpt-oss | OpenAI |
| Mistral | Mistral AI |

> **Mental Model: Weights Are the Brain, the Runner Is the Body**
> A downloaded model file is just a brain in a jar. A **runner** like Ollama gives it a body: it loads the model into memory, accepts your messages, and returns answers.

## 4. Ollama: Local and Cloud in One Tool

**Ollama** is the most widely used tool for running open models. In 2026 it handles both:

| Mode | Model tag example | Where it runs |
|---|---|---|
| Local | `gemma4:e2b` | Your computer |
| Cloud | `gemma4:31b-cloud` | Ollama's servers |

Cloud models use a `-cloud` or `:cloud` suffix. You don't download them, and they don't use your disk space or VRAM. **The commands and Python code stay the same.** Only the model name changes.

> **Mental Model: One Remote, Two TVs**
> Ollama is a single remote control. Point it at a local model or a cloud model; the buttons don't change.

## 7. Streaming: Why Answers Appear Word by Word

From Lesson 1.1: LLMs are **autoregressive** and generate one token at a time. **Streaming** sends each token to you the moment it is ready instead of waiting for the full answer.

| | Without streaming | With streaming |
|---|---|---|
| User experience | Blank screen, then the full answer | Text appears instantly, word by word |
| Time to first word | Several seconds | Under a second |
| Used in | Background jobs, batch processing | Every chat product (ChatGPT, Claude, Gemini) |

> **Mental Model: Download vs Live Stream**
> Without streaming, you download a whole movie before watching. With streaming, you watch while it loads. Same content, much better experience.

## 8. Your First GenAI Script: A Customer Support Assistant

Every company with customers needs fast, polite replies. This script turns a local model into a support assistant that streams its answer.

In `main.py` with:

```python
from ollama import chat

MODEL = "gemma4:e2b"  # change to "gemma4:31b-cloud" to use the cloud

SYSTEM_PROMPT = (
    "You are a professional customer support assistant for an online store. "
    "Reply politely, give clear next steps, and keep answers under 80 words."
)


def ask_support(question: str) -> None:
    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": question},
    ]

    stream = chat(model=MODEL, messages=messages, stream=True)

    for chunk in stream:
        print(chunk.message.content, end="", flush=True)
    print()


if __name__ == "__main__":
    ask_support("My order arrived damaged. What should I do?")
```

Run it:
```bash
uv run main.py
```

**Switch to cloud:** run `ollama signin` once, change `MODEL` to `"gemma4:31b-cloud"`, and run again. Nothing else changes.

### How the Script Works

| Part | GenAI concept |
|---|---|
| `MODEL` | Which model answers: local or cloud |
| `SYSTEM_PROMPT` | The model's role and rules; it shapes every reply |
| `messages` | The conversation, as a list of messages with roles |
| `"role": "system"` | Instructions from the developer |
| `"role": "user"` | The end user's question |
| `chat(...)` | Sends the conversation to the model |
| `stream=True` | Return tokens one by one instead of all at once |
| `for chunk in stream` | Print each piece as it arrives |

> **Mental Model: The Message List Is a Script for a Play**
> The **system** message is the director's notes. The **user** message is the audience's question. The model plays the **assistant** role and performs its line. This same `messages` format is used by OpenAI, Anthropic, Gemini, and Ollama, so what you learn here works everywhere.

## 9. Python Concepts Behind the Script

Skip this section if you are comfortable with Python.

| Code | Python concept | Meaning |
|---|---|---|
| `from ollama import chat` | Import | Bring the `chat` function from the installed package |
| `MODEL = "..."` | Constant (uppercase naming) | A value set once and not changed |
| `( "..." "..." )` | Implicit string joining | Adjacent strings inside brackets join into one |
| `def ask_support(question: str) -> None:` | Function with type hints | Takes a string and returns nothing |
| `[ {...}, {...} ]` | List of dictionaries | An ordered collection of key-value records |
| `chat(model=..., stream=True)` | Keyword arguments | Pass values by name, which makes calls clearer |
| `for chunk in stream:` | Iterating a generator | Pull values one at a time as they are produced |
| `print(..., end="", flush=True)` | Print options | Stay on the same line and show text immediately |
| `if __name__ == "__main__":` | Entry point guard | Run this only when the file is executed directly |

### Build the Streaming Idea Yourself

Streaming is just a Python **generator**: a function that uses `yield` to hand out values one at a time.

```python
import time


def fake_llm(answer: str):
    for word in answer.split():
        time.sleep(0.2)       # pretend the model is thinking
        yield word + " "      # hand out one piece, then pause


for token in fake_llm("Please share a photo of the damaged item and we will send a replacement."):
    print(token, end="", flush=True)
print()
```

Run it and watch the words appear one by one. This is the same pattern the Ollama SDK uses: the real model **yields** tokens, and your `for` loop **receives** them.

> **Mental Model: Generator = Tap, List = Bucket**
> A list gives you a full bucket of water at once. A generator is a tap: water flows only as you need it. Streaming LLM responses are a tap.

## Key Takeaways

1. **Local AI** runs on your machine: it's private, free, and works offline. **Cloud AI** gives you more power.
2. **Open-weight models** plus a **runner** like Ollama make local GenAI possible.
3. In 2026, **Ollama runs both local and cloud models** with the same code; only the model name changes.
4. **Streaming** delivers tokens as they are generated and is standard in every GenAI product.
5. The **messages list with roles** (system, user, assistant) is the universal format across all GenAI SDKs.

**Practice:** Change `SYSTEM_PROMPT` so the assistant works for a different business (a bank, a university, or a clinic), and test it with three different questions.
