### 2.3 Generation Settings: temperature, top_p, max tokens

---

## 1. How the Model Picks the Next Token

From Lesson 1.1: an LLM writes **one token at a time**. At every step, it does not "know" the next word. It calculates a **probability for every token** in its vocabulary, then **picks one**.

Prompt: *"The best city to visit in Pakistan is"*

| Candidate token | Probability |
|---|---|
| Lahore | 43.9% |
| Islamabad | 26.6% |
| Karachi | 16.1% |
| Hunza | 9.8% |
| Skardu | 3.6% |

**Generation settings control how that pick is made.** The model's knowledge stays the same; only the choosing changes.

> **Mental Model: The Weighted Dice**
> At each step the model rolls a weighted die. Lahore has the biggest face, Skardu the smallest. **Temperature** reshapes the die, **top_p** removes the smallest faces, and **max_tokens** limits how many times you roll.

---

## 2. Temperature: How Adventurous the Model Is

**Temperature reshapes the probabilities before the pick.**

- **Low temperature** makes the top token even more likely. Answers become focused and repeatable.
- **High temperature** flattens the probabilities. Less likely tokens get a real chance. Answers become varied and creative, and at very high values, random.

The same five candidates at different temperatures (calculated by the script in Section 8):

| Temperature | Lahore | Islamabad | Karachi | Hunza | Skardu |
|---|---|---|---|---|---|
| **0.2** | 91.8% | 7.5% | 0.6% | 0.1% | 0.0% |
| **0.7** | 53.3% | 26.1% | 12.8% | 6.3% | 1.5% |
| **1.0** | 43.9% | 26.6% | 16.1% | 9.8% | 3.6% |
| **1.5** | 35.9% | 25.7% | 18.4% | 13.2% | 6.8% |

At **temperature 0**, the model always picks the top token (this is called **greedy decoding**).

> **Mental Model: The Spice Level**
> Temperature is the spice level. 0 is plain rice: safe and identical every time. 0.7 is a balanced karahi. 1.5 is extra hot: exciting, but it can go wrong.

---

## 3. top_p: How Many Candidates Are Allowed

**top_p (nucleus sampling)** keeps only the most likely tokens whose probabilities **add up to p**, and removes the rest before the pick.

Using the temperature 1.0 probabilities:

| top_p | Candidates kept | Removed |
|---|---|---|
| 0.5 | Lahore, Islamabad | Karachi, Hunza, Skardu |
| 0.9 | Lahore, Islamabad, Karachi, Hunza | Skardu |
| 1.0 | All five | None |

Lower top_p removes the "long tail" of unlikely tokens, which reduces strange or off-topic words.

**Related setting: top_k** keeps only the top **k** tokens (for example, `top_k=40`). It is supported by Ollama, Gemini, and Claude, but **not** by the OpenAI API.

> **Mental Model: The Shortlist**
> Temperature decides how fair the competition is. top_p decides who is allowed on the shortlist in the first place.

**Industry rule:** adjust **temperature or top_p, not both.** Most teams tune temperature and leave top_p at its default.

---

## 4. max_tokens: How Long the Answer Can Be

`max_tokens` is a hard cap on **output tokens**. It does not make answers shorter or better written; it **cuts them off**.

| Why set it | What happens |
|---|---|
| Control cost | Output tokens are the most expensive part of a request |
| Control speed | Fewer tokens means a faster response |
| Protect your app | Prevents runaway, very long answers |

Always check **`finish_reason`** (Lesson 2.1):

| finish_reason | Meaning |
|---|---|
| `"stop"` | The model finished naturally, or hit a stop sequence |
| `"length"` | The answer was cut off at `max_tokens` |

To get **shorter** answers, ask for them in the prompt ("Answer in 2 sentences"). Use `max_tokens` as a safety limit, not as a writing instruction.

---

## 5. Other Useful Settings

| Setting | What it does | Typical value | Supported by |
|---|---|---|---|
| `stop` | Stop generating when this text appears | `["\n\n", "END"]` | OpenAI, Ollama, Gemini, Claude |
| `seed` | Makes sampling repeatable (best effort, not guaranteed) | `42` | OpenAI-compatible APIs, Ollama |
| `frequency_penalty` | Discourages repeating the same tokens | `0` to `1` | OpenAI, Ollama |
| `presence_penalty` | Encourages new topics | `0` to `1` | OpenAI, Ollama |
| `top_k` | Keep only the top k tokens | `40` | Ollama, Gemini, Claude |
| `num_ctx` (Ollama) | Context window size (Lesson 2.2) | `8192` | Ollama |

---

## 6. Important in 2026: Reasoning Models Restrict Sampling

Many 2026 frontier models **reason (think) before answering**, and they control their own sampling. For example, OpenAI's **GPT-5.5 and later** reason by default and **reject custom `temperature` and `top_p` with an error**, unless reasoning is turned off with `reasoning_effort="none"`. Reasoning models also use `max_completion_tokens` instead of `max_tokens`, because hidden reasoning tokens count toward the limit.

| Model type | temperature / top_p | Length limit |
|---|---|---|
| Classic and open models (Gemma, Llama, Qwen via Ollama) | Fully supported | `max_tokens` |
| Gemini via OpenAI-compatible API | Supported | `max_tokens` |
| OpenAI GPT-5.5+ (reasoning on) | Not allowed | `max_completion_tokens` |
| OpenAI GPT-5.5+ with `reasoning_effort="none"` | Allowed | `max_completion_tokens` |

Always check the model's documentation before setting sampling parameters.

---

## 7. Recommended Settings by Task

| Task | temperature | max_tokens | Why |
|---|---|---|---|
| Classification, extraction, JSON | 0 | Small (50–200) | Same input should give the same output |
| Customer support answers | 0.2–0.4 | 200–400 | Accurate and consistent, slightly natural |
| Summaries and explanations | 0.3–0.5 | 300–800 | Faithful to the source |
| General chat | 0.7 | 500–1000 | Natural and varied |
| Marketing copy, brainstorming | 0.9–1.2 | 300–600 | Variety and creativity |
| Code generation | 0–0.2 | Depends on task | Correctness over creativity |

> **Mental Model: Facts Cold, Ideas Warm**
> If there is one right answer, keep temperature **cold** (0–0.3). If you want many good ideas, make it **warm** (0.8–1.2).

### Example 0: See the Math (No Model Needed)

Create `sampling_demo.py`. This is the script that produced the tables in Sections 2 and 3.

```python
import math

scores = {"Lahore": 3.0, "Islamabad": 2.5, "Karachi": 2.0, "Hunza": 1.5, "Skardu": 0.5}


def probabilities(scores: dict[str, float], temperature: float) -> dict[str, float]:
    scaled = {word: score / temperature for word, score in scores.items()}
    total = sum(math.exp(value) for value in scaled.values())
    return {word: math.exp(value) / total for word, value in scaled.items()}


def top_p_filter(probs: dict[str, float], top_p: float) -> list[str]:
    kept, cumulative = [], 0.0
    for word, p in sorted(probs.items(), key=lambda item: item[1], reverse=True):
        kept.append(word)
        cumulative += p
        if cumulative >= top_p:
            break
    return kept


for temperature in [0.2, 0.7, 1.0, 1.5]:
    probs = probabilities(scores, temperature)
    row = "  ".join(f"{word} {p:5.1%}" for word, p in probs.items())
    print(f"T={temperature}:  {row}")

print()
probs = probabilities(scores, 1.0)
for top_p in [0.5, 0.9, 1.0]:
    print(f"top_p={top_p}: candidates = {top_p_filter(probs, top_p)}")
```

```bash
uv run sampling_demo.py
```

| Code | Meaning |
|---|---|
| `scores` | The model's raw scores for each candidate (called **logits**) |
| `score / temperature` | The key step: dividing by a small temperature makes gaps bigger; a large temperature makes them smaller |
| `math.exp(...) / total` | **Softmax**: turns scores into probabilities that add up to 100% |
| `top_p_filter` | Keeps the most likely candidates until their total reaches `top_p` |

## 9. OpenAI Python SDK Examples

All examples use `get_client()` from `llm.py` (Lesson 1.3).

### Example 1: Temperature Comparison

Create `openai_temperature.py`:

```python
from llm import get_client

client, model = get_client()

PROMPT = "Suggest a name for a new chai cafe in Lahore. Reply with the name only."

for temperature in [0.0, 0.7, 1.3]:
    print(f"\ntemperature={temperature}")
    for attempt in range(3):
        response = client.chat.completions.create(
            model=model,
            messages=[{"role": "user", "content": PROMPT}],
            temperature=temperature,
            max_tokens=20,
        )
        print(f"  {attempt + 1}. {response.choices[0].message.content.strip()}")
```

**What to notice:** at 0.0 the three names are usually identical. At 0.7 they vary. At 1.3 they become more unusual.

### Example 2: top_p Comparison

Create `openai_top_p.py`:

```python
from llm import get_client

client, model = get_client()

PROMPT = "Write one creative sentence about the rain in Islamabad."

for top_p in [0.1, 0.9]:
    print(f"\ntop_p={top_p}")
    for attempt in range(3):
        response = client.chat.completions.create(
            model=model,
            messages=[{"role": "user", "content": PROMPT}],
            temperature=1.0,
            top_p=top_p,
            max_tokens=60,
        )
        print(f"  {attempt + 1}. {response.choices[0].message.content.strip()}")
```

**What to notice:** with `top_p=0.1`, only the very top tokens are allowed, so the sentences are almost the same even at temperature 1.0. With `top_p=0.9`, they vary.

### Example 3: max_tokens, finish_reason, and stop

Create `openai_limits.py`:

```python
from llm import get_client

client, model = get_client()

messages = [{"role": "user", "content": "List 5 tips for a job interview, one per line, numbered."}]

# 1. Cut off by max_tokens
short = client.chat.completions.create(model=model, messages=messages, max_tokens=25)
print("max_tokens=25 ->", short.choices[0].finish_reason)
print(short.choices[0].message.content, "\n")

# 2. Enough room to finish
full = client.chat.completions.create(model=model, messages=messages, max_tokens=300)
print("max_tokens=300 ->", full.choices[0].finish_reason)
print(full.choices[0].message.content, "\n")

# 3. Stop early at a stop sequence
stopped = client.chat.completions.create(model=model, messages=messages, max_tokens=300, stop=["3."])
print("stop=['3.'] ->", stopped.choices[0].finish_reason)
print(stopped.choices[0].message.content)
```

**What to notice:** the first answer ends with `finish_reason="length"` in the middle of a tip. The third answer stops before tip 3 with `finish_reason="stop"`, because it reached the stop sequence.

### Example 4: Reproducible Output with seed

Create `openai_seed.py`:

```python
from llm import get_client

client, model = get_client()

PROMPT = "Invent a short motto for a computer science society."

for run in range(3):
    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": PROMPT}],
        temperature=0.9,
        seed=42,
        max_tokens=30,
    )
    print(f"Run {run + 1}: {response.choices[0].message.content.strip()}")
```

**What to notice:** with the same `seed`, the "random" choices repeat, so the three mottos usually match even at temperature 0.9. Remove `seed=42` and run again to compare. Seeds are **best effort**: providers do not guarantee identical output.

### Example 5: Task Presets (System Approach)

In real projects, settings live in one place, not scattered across scripts. Create `presets.py`:

```python
from llm import get_client

client, model = get_client()

PRESETS = {
    "classify": {"temperature": 0.0, "max_tokens": 10},
    "support": {"temperature": 0.3, "max_tokens": 200},
    "creative": {"temperature": 1.0, "max_tokens": 150},
}


def generate(task: str, prompt: str) -> str:
    settings = PRESETS[task]
    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
        **settings,
    )
    return response.choices[0].message.content.strip()


print(generate("classify", "Classify the sentiment as positive, negative, or neutral: 'Delivery was late again.'"))
print(generate("support", "A customer's order is late. Write a short apology with next steps."))
print(generate("creative", "Write a two-line slogan for an online bookstore in Pakistan."))
```

| Code | Meaning |
|---|---|
| `PRESETS` | One dictionary of settings per task type |
| `**settings` | Unpacks the dictionary into keyword arguments (`temperature=..., max_tokens=...`) |

### Example 6: OpenAI Reasoning Models (GPT-5.5 and Later)

Only run this with `PROVIDER=openai`. It shows the 2026 rule from Section 6.

```python
from llm import get_client

client, model = get_client("openai")

response = client.chat.completions.create(
    model=model,
    messages=[{"role": "user", "content": "Suggest a name for a chai cafe. Name only."}],
    reasoning_effort="none",       # turn reasoning off so temperature is allowed
    temperature=0.9,
    max_completion_tokens=20,      # reasoning models use this instead of max_tokens
)

print(response.choices[0].message.content)
```

Remove `reasoning_effort="none"` and the API returns an error for `temperature`.

## 10. LangChain Examples

LangChain uses the same settings, passed when you **create** the model.

### Example 7: ChatOllama with Generation Settings

Create `lc_settings.py`:

```python
from langchain_ollama import ChatOllama

llm = ChatOllama(
    model="gemma4:e2b",
    temperature=0.3,
    top_p=0.9,
    top_k=40,
    num_predict=150,   # Ollama's name for max_tokens
    seed=42,
    stop=["\n\n"],
)

response = llm.invoke("Give one practical tip for learning Python faster.")

print(response.content)
print(response.response_metadata.get("done_reason"))
```

| Parameter | Meaning |
|---|---|
| `temperature`, `top_p`, `top_k` | Sampling settings from Sections 2 and 3 |
| `num_predict` | Maximum output tokens (Ollama's name for `max_tokens`) |
| `seed` | Repeatable sampling |
| `stop` | Stop at a blank line |
| `response_metadata["done_reason"]` | Ollama's finish reason: `"stop"` or `"length"` |

### Example 8: Provider-Independent Models with init_chat_model

`init_chat_model` creates a chat model from a `"provider:model"` string. Settings like `temperature` and `max_tokens` are passed the same way for every provider.

Create `lc_init.py`:

```python
from langchain.chat_models import init_chat_model

PROMPT = "Suggest a name for a new chai cafe in Lahore. Reply with the name only."

focused = init_chat_model("ollama:gemma4:e2b", temperature=0.0, num_predict=20)
creative = init_chat_model("ollama:gemma4:e2b", temperature=1.3, num_predict=20)

print("Focused: ", [focused.invoke(PROMPT).content.strip() for _ in range(3)])
print("Creative:", [creative.invoke(PROMPT).content.strip() for _ in range(3)])
```

To switch providers later, change only the model string, for example `"openai:gpt-5.5"` or `"anthropic:claude-sonnet-5-5"` (and use `max_tokens` instead of the Ollama-specific `num_predict`).

### Example 9: Change Settings at Runtime with configurable_fields

Sometimes the same app needs different settings per request. `configurable_fields` lets you choose them at call time, without creating new models.

Create `lc_configurable.py`:

```python
from langchain.chat_models import init_chat_model

llm = init_chat_model(
    "ollama:gemma4:e2b",
    temperature=0.0,
    num_predict=60,
    configurable_fields=("temperature", "num_predict"),
)

prompt = "Write a one-line welcome message for new students."

print("Default:  ", llm.invoke(prompt).content)

print("Creative: ", llm.invoke(
    prompt,
    config={"configurable": {"temperature": 1.2}},
).content)

print("Very short:", llm.invoke(
    prompt,
    config={"configurable": {"num_predict": 8}},
).content)
```

| Code | Meaning |
|---|---|
| `configurable_fields=(...)` | Which settings can change per request |
| `config={"configurable": {...}}` | The settings for this one call |

### Example 10: Run Many Prompts at Once with batch

`batch` sends several inputs in parallel. It is a fast way to compare settings or process many items.

Create `lc_batch.py`:

```python
from langchain_ollama import ChatOllama

classifier = ChatOllama(model="gemma4:e2b", temperature=0.0, num_predict=5)

reviews = [
    "Excellent quality, fast delivery.",
    "The item stopped working after a week.",
    "It is okay, nothing special.",
]

prompts = [
    f"Classify the sentiment as positive, negative, or neutral. One word only.\nReview: {review}"
    for review in reviews
]

for review, response in zip(reviews, classifier.batch(prompts)):
    print(f"{response.content.strip():<10} <- {review}")
```

**What to notice:** classification uses **temperature 0** and a **tiny token limit**: one right answer, and only one word needed.

| Finish reason | `choices[0].finish_reason` | `response_metadata["finish_reason"]` | `response_metadata["done_reason"]` |

## Key Takeaways

1. At every step, the model calculates **probabilities** for the next token; generation settings control **how it picks**.
2. **Temperature** reshapes the probabilities: low is focused and repeatable, high is varied and creative.
3. **top_p** keeps only the most likely tokens that add up to p. Tune temperature **or** top_p, not both.
4. **max_tokens** is a hard cut-off for cost and safety; check `finish_reason` for `"length"`.
5. Use **cold settings for facts** (classification, extraction, code) and **warm settings for ideas** (brainstorming, copy).
6. In 2026, many **reasoning models restrict** temperature and top_p. Always check the model's documentation.
