### 2.1 Tokens and Tokenization

---

## 1. What Is a Token?

**A token is the smallest piece of text an LLM reads or writes.** It can be a whole word, part of a word, a space plus a word, a number, or a punctuation mark.

LLMs never see letters or words directly. Every piece of text is first cut into tokens, and each token is turned into a number (its **token ID**). The model only works with these numbers.

```text
Text:     "Tokenization is powerful"
Tokens:   ["Token", "ization", " is", " powerful"]
Token IDs: [ 4421,   2860,     382,  8848 ]      (example IDs)
```

> **Mental Model: LEGO Bricks**
> Text is a finished LEGO model. Tokenization breaks it into standard bricks. The LLM has a fixed box of bricks (its **vocabulary**) and builds every answer by placing one brick at a time.

---

## 2. Why Not Use Words or Characters?

| Approach | Problem | Example |
|---|---|---|
| **Characters** | Too many tiny pieces; slow and expensive | "cat" becomes 3 pieces |
| **Whole words** | Vocabulary becomes huge, and new words break the model | "ChatGPT", "uv", or a new name is "unknown" |
| **Subword tokens** | Balanced: common words stay whole, rare words split into known parts | "unbelievable" becomes "un" + "believ" + "able" |

Modern LLMs use **subword tokenization**, so they can handle any text, including new words, names, code, and emojis, using a fixed vocabulary.

---

## 3. How Tokenization Works: Byte Pair Encoding (BPE)

Most LLMs use **Byte Pair Encoding (BPE)** or a close variant. The idea is simple:

1. Start with single characters (bytes).
2. Find the pair that appears together most often in a huge amount of text.
3. Merge that pair into a new token.
4. Repeat thousands of times until the vocabulary reaches the target size.

| Step | Most frequent pair | New token | "lower" is now split as |
|---|---|---|---|
| Start | - | - | l, o, w, e, r |
| 1 | `l` + `o` | `lo` | lo, w, e, r |
| 2 | `lo` + `w` | `low` | low, e, r |
| 3 | `e` + `r` | `er` | low, er |
| 4 | `low` + `er` | `lower` | lower |

Frequent words end up as **one token**. Rare words stay as **several tokens**.

> **Mental Model: Text Messaging Shortcuts**
> People who text a lot invent shortcuts for the phrases they type most often ("brb", "idk"). BPE does the same: the most frequent letter combinations get their own single token.

### Every Model Has Its Own Tokenizer

| Model family | Tokenizer | Vocabulary size |
|---|---|---|
| OpenAI GPT (GPT-4o and later) | `o200k_base` | About 200,000 tokens |
| Meta Llama 3 and later | BPE (tiktoken-based) | About 128,000 tokens |
| Google Gemma 4 | SentencePiece | About 262,000 tokens |

The same sentence gives **different token counts** on different models. Always measure with the model you actually use.

---

## 4. Token Rules of Thumb

For English text:

| Rule | Approximate value |
|---|---|
| 1 token | About 4 characters |
| 1 token | About 0.75 words |
| 100 tokens | About 75 words |
| 1 page of text | About 500 to 700 tokens |

Things that use **more** tokens than you might expect:

| Text type | Why |
|---|---|
| Urdu, Arabic, Hindi, and other non-English text | Tokenizers are trained mostly on English, so these scripts are often split into more pieces |
| Long numbers (`1234567890`) | Split into several chunks of digits |
| Code | Spaces, brackets, and symbols are separate tokens |
| Rare names and technical terms | Not in the vocabulary as whole words |

> **Mental Model: The Taxi Meter**
> Every token is a tick on a taxi meter. Long prompts, long answers, and non-English text all make the meter run faster.

---

## 5. Why Tokens Matter for Developers

| Area | How tokens affect it |
|---|---|
| **Cost** | Cloud APIs charge per input token and per output token (output is usually more expensive) |
| **Context window** | Every model has a maximum number of tokens it can handle at once (covered in Lesson 2.2) |
| **Speed** | The model generates one token at a time, so longer answers take longer |
| **Output limit** | `max_tokens` caps how many tokens the model may generate |

### Cost Example

Prices below are **illustrative only**. Always check the provider's current pricing page.

| Item | Value |
|---|---|
| Input price | $1.00 per 1 million tokens |
| Output price | $4.00 per 1 million tokens |
| One support chat | 800 input tokens + 200 output tokens |
| Cost of one chat | (800 x $1 + 200 x $4) / 1,000,000 = **$0.0016** |
| 100,000 chats per month | **$160** |

A small saving per request becomes a large saving at scale. This is why companies care about tokens.

## 7. Script 1: See the Tokens

Create `see_tokens.py`:

```python
import tiktoken

encoding = tiktoken.get_encoding("o200k_base")

texts = [
    "Hello world",
    "unbelievable",
    "Tokenization is powerful",
    "My order number is 4829301756",
    "Mera naam Ali hai",
    "میرا نام علی ہے",
]

for text in texts:
    token_ids = encoding.encode(text)
    pieces = [encoding.decode([token_id]) for token_id in token_ids]
    print(f"{text!r}")
    print(f"  tokens: {len(token_ids)}  pieces: {pieces}")
```

```bash
uv run see_tokens.py
```

The first run downloads the tokenizer file, so it needs internet.

**What to notice:**
- Common English words are usually one token each.
- The long number is split into several pieces.
- The same sentence in Urdu script usually needs more tokens than in Roman Urdu or English.

| Code | Meaning |
|---|---|
| `get_encoding("o200k_base")` | Load the tokenizer used by modern OpenAI models |
| `encoding.encode(text)` | Text to a list of token IDs |
| `encoding.decode([token_id])` | One token ID back to its text piece |
| `len(token_ids)` | The token count |

## 8. Script 2: Measure Real Token Usage

The `tiktoken` count is a good estimate, but the **provider's own count** is what you are billed for. Every API response reports it.

Create `token_usage.py` (uses `llm.py` from Lesson 1.3):

```python
from llm import get_client

client, model = get_client()

response = client.chat.completions.create(
    model=model,
    messages=[{"role": "user", "content": "Explain what a token is in 3 sentences."}],
    max_tokens=40,
)

choice = response.choices[0]
usage = response.usage

print(choice.message.content)
print("-" * 40)
print("Input tokens: ", usage.prompt_tokens)
print("Output tokens:", usage.completion_tokens)
print("Total tokens: ", usage.total_tokens)
print("Finish reason:", choice.finish_reason)
```

```bash
uv run token_usage.py
```

| Field | Meaning |
|---|---|
| `usage.prompt_tokens` | Tokens you sent (input) |
| `usage.completion_tokens` | Tokens the model wrote (output) |
| `max_tokens=40` | Stop after 40 output tokens at most |
| `finish_reason` | `"stop"` = the model finished naturally; `"length"` = it hit `max_tokens` and was cut off |

Run it again with `max_tokens=200` and compare the finish reason.

**Note for OpenAI's own models:** newer OpenAI reasoning models use `max_completion_tokens` instead of `max_tokens`, and they spend some tokens on hidden reasoning. With a very small limit you may get an empty reply. Run this script with `PROVIDER=ollama` or `PROVIDER=gemini` for the clearest result.

> **Mental Model: The Word Limit on an Exam**
> `max_tokens` is a strict word limit. If the model reaches it, the answer is cut off mid-sentence, and `finish_reason` tells you so. In production, always check it.

## 9. Script 3: LangChain with Ollama

**LangChain** is a popular framework that gives every model provider the same interface. You will use it more in later modules; here is the simplest possible example.

Create `langchain_tokens.py`:

```python
from langchain_ollama import ChatOllama

llm = ChatOllama(model="gemma3:1b", temperature=0)

response = llm.invoke("In one sentence, what is tokenization?")

print(response.content)
print(response.usage_metadata)
```

```bash
uv run langchain_tokens.py
```

Example output (your text and numbers will differ):

```text
Tokenization is the process of breaking down text into smaller units, like words or phrases, that can be processed by computers.

{'input_tokens': 19, 'output_tokens': 27, 'total_tokens': 46}
```

| Code | Meaning |
|---|---|
| `ChatOllama(model=..., temperature=0)` | A LangChain chat model backed by your local Ollama model |
| `llm.invoke("...")` | Send one message and wait for the full reply |
| `response.content` | The reply text |
| `response.usage_metadata` | Token counts in LangChain's standard format |

### SDK vs LangChain: Same Idea, Different Style

| | `openai` SDK | LangChain |
|---|---|---|
| Call | `client.chat.completions.create(...)` | `llm.invoke(...)` |
| Reply text | `response.choices[0].message.content` | `response.content` |
| Token counts | `response.usage` | `response.usage_metadata` |
| Switch provider | Change `base_url` and model | Swap the class (`ChatOllama`, `ChatOpenAI`, `ChatAnthropic`) |

> **Mental Model: Universal Remote**
> LangChain is a universal remote: one set of buttons (`invoke`, `stream`, `usage_metadata`) for every brand of model.

## 10. Token-Saving Habits

| Habit | Why it helps |
|---|---|
| Keep system prompts short and clear | They are sent with every request |
| Set `max_tokens` | Prevents runaway long answers and surprise bills |
| Ask for short or structured answers | Fewer output tokens, and output tokens cost more |
| Send only the relevant text | Don't paste a whole document when one section is enough |
| Measure with real usage data | Estimates can be off; billing uses the provider's count |

---

## Key Takeaways

1. A **token** is a piece of text (often part of a word) and the basic unit of every LLM.
2. **Tokenization** turns text into token IDs; most LLMs use **BPE** subword tokenization.
3. Each model family has its **own tokenizer**, so token counts differ between models.
4. Rule of thumb for English: **1 token is about 4 characters or 0.75 words**. Non-English text, numbers, and code often use more.
5. Tokens drive **cost, speed, context limits, and output limits**.
6. Use `response.usage` (SDK) or `response.usage_metadata` (LangChain) to measure real usage, and check `finish_reason` for cut-off answers.

**Practice:** Write one customer support question in English, Roman Urdu, and Urdu script. Count the tokens for each with `see_tokens.py`, then send each to your model with `token_usage.py` and compare the input token counts.
