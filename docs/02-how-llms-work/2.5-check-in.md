**13.** The model keeps no memory between requests; each call starts fresh. To build a chatbot, the application must store the conversation and send the relevant history with every request, and manage its size so it fits the context window.

**14.** A sliding window keeps the last N turns; token trimming keeps the newest messages that fit a token budget, which is more precise because messages differ in length. Both drop older messages, so early facts (like the user's name) can be forgotten. Summarization or long-term memory can help.

**15.** Sentiment classifier: temperature 0 and a small token limit, because there is one correct label and it should be repeatable. Slogan generator: temperature around 0.9 to 1.2, because variety and creativity are the goal.

**16.** The model's knowledge cutoff may be before newer Python releases, so it may present an old version as the latest. Fixes: put today's date in the system prompt and instruct it to say when its information may be outdated; pass current information in the prompt (from a website, database, or search); use web search or RAG.

### Part C

**C1.** The assistant's reply is never added to `messages`, so the model never sees its own previous answers. Add it after each response:

```python
    reply = response.choices[0].message.content
    messages.append({"role": "assistant", "content": reply})
    print(reply)
```

(In this two-turn example the name still appears in the user's earlier message, but in longer chats, missing assistant turns break the conversation. Always store both sides.)

**C2.** `finish_reason` will be `"length"`. The answer will be only a few words long and cut off mid-sentence, because 10 tokens is far too few for a detailed history.

**C3.** GPT-5.5 reasons by default and rejects custom `temperature`. It also uses `max_completion_tokens` instead of `max_tokens`. Fix either way:

```python
response = client.chat.completions.create(
    model="gpt-5.5",
    messages=[{"role": "user", "content": "Suggest a cafe name."}],
    reasoning_effort="none",
    temperature=0.9,
    max_completion_tokens=20,
)
```

or remove `temperature` and keep reasoning on.

**C4.** `ConversationBufferMemory` and `ConversationChain` are legacy classes, deprecated since LangChain 0.3.1 and moved to the `langchain-classic` package in LangChain 1.0. These imports fail in current `langchain`. Use a plain message list with `llm.invoke(messages)` for simple scripts, or a LangGraph checkpointer (`InMemorySaver` with `thread_id`) for real apps.

**C5.**
- a) (2,000 x $2 + 500 x $10) / 1,000,000 = (4,000 + 5,000) / 1,000,000 = **$0.009** per conversation.
- b) $0.009 x 50,000 = **$450** per month.
- c) Any two: use a smaller or cheaper model; trim or summarize history to cut input tokens; set `max_tokens` and ask for shorter answers; use prompt caching for the repeated system prompt; use a local model where quality allows.

**C6.** The model receives 4 messages: the system prompt, "Do you offer a warranty?", the warranty answer, and "What is my name and what did I order?". Ali's introduction was trimmed away, so the model **cannot** correctly answer his name or order.
